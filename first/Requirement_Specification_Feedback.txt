[피드백 및 수정/추가안] 2124066_정훈_프로젝트 요구분석 명세서
================================================================================

정훈님께서 작성하신 요구분석 명세서는 프로젝트의 배경, 요구사항 도출 기법(사용자/시스템 분리), 
기술 스택(Firebase Auth, Firestore, React, Canvas, Android Geofencing 등)에 기반한 구체적 해결 방안, 
그리고 상세 시나리오까지 소프트웨어 공학적 템플릿에 맞춰 매우 완성도 높게 잘 작성되어 있습니다.

기존에 명세되어 있는 즐겨찾기, 실시간 도면 안내, 외부 내비 연동 및 지오펜싱 복귀 프로세스는 
체계적으로 반영되어 있어 그대로 유지하셔도 좋습니다.

다만, 향후 구현할 예정인 "주차 위치 저장 및 출차 시 위치 확인 기능"은 현재 문서에 누락되어 있으므로, 
이 요구사항을 반영하기 위해 문서의 각 장(Chapter)별로 수정 및 추가해야 할 구체적인 내용을 아래와 같이 정리해 드립니다. 
본 내용을 그대로 명세서 한글(HWP) 파일에 복사/붙여넣기하여 반영하시면 됩니다.

또한, 문서 검토 과정에서 발견된 마이너한 오류(목차/번호 중복 등)에 대한 수정 권고사항도 함께 기재했습니다.

-> 기존 5번(즐겨찾기) 항목 뒤에 6번 항목으로 아래 내용을 추가합니다.

   - 사용자가 주차 완료 후 현재 주차한 구역(예: A구역 3번)을 상세 도면 상에서 탭하거나 직접 입력하여 주차 위치를 기록합니다.
   - 추후 출차 시, 모바일 앱 메인화면 혹은 프로필 화면에서 '내 차 위치 확인'을 수행하면 저장된 위치의 주차장 도면과 구체적인 주차 칸 위치(차량 마커 오버레이)를 즉각 시각적으로 매핑하여 제공합니다.

### [추가 사항 3] 2. 프로젝트 요구사항 -> 2.3 기능적 요구사항 (표 수정)

-> 기능적 요구사항 테이블의 FR-06 아래에 FR-07 항목을 새롭게 추가합니다.

* ID: FR-07
* 기능명: 주차 위치 등록 및 출차 위치 확인
* 우선순위: 2
* 해결 방안: 
  사용자가 주차 후 모바일 앱 상세 도면에서 자신이 주차한 구획을 선택하여 [주차 위치 등록]을 요청하면, 사용자의 UID와 주차장 ID, 주차 구획 ID를 매핑하여 Firestore에 저장합니다. 이후 출차 시 해당 정보를 호출하여 주차 도면 상의 매핑 위치에 사용자 차량 전용 아이콘(커스텀 마커)을 오버레이 표시하여 시각화합니다.

-> 하단 영역 및 상세 정보 시트 설명 항목 또는 주차장 상세 도면 뷰어 설명 부분에 아래 내용을 녹여냅니다.

- 주차 위치 제어 인터페이스: 주차장 상세 도면 진입 시 사용자가 주차한 상태가 아닐 때는 비어있는 구획을 터치하여 '내 차 주차 위치로 등록'할 수 있는 플로팅 액션 버튼(FAB) 또는 팝업 메뉴가 활성화됩니다.

### [추가 사항 6] 4. 프로젝트 기능 시나리오

-> 4.3 시나리오 밑에 새로운 항목으로 4.4 시나리오를 추가합니다.

4.4 주요기능-4 시나리오(일반 사용자, 주차 위치 저장 및 출차 확인)
출장차 낯선 대형 쇼핑몰 주차장을 찾은 운전자 D씨는 지오펜싱 복귀 알림을 통해 자동으로 열린 본 주차 앱의 상세 도면을 보고 기둥 옆 빈칸인 'C구역 12번' 칸에 안전하게 주차합니다. 차에서 내리기 전 D씨는 모바일 앱 화면에 켜져 있는 도면에서 C구역 12번 사각형을 터치한 후 나타나는 [이 자리에 주차 완료] 버튼을 누릅니다. 시스템은 D씨의 주차 위치 정보를 데이터베이스에 실시간 기록합니다.
볼일을 마치고 3시간 후에 주차장으로 복귀한 D씨는 차를 세워둔 위치가 정확히 기억나지 않아 앱을 켭니다. 앱 메인 화면 상단에 활성화된 [내 차 위치 찾기] 퀵 배너를 터치하자, 쇼핑몰 주차장의 전체 도면이 로드되면서 D씨가 주차했던 C구역 12번 위치에 깜빡이는 차량 핀 마커가 시각적으로 노출됩니다. D씨는 도면 지도를 보며 헤매지 않고 최단 동선으로 이동해 본인의 차량을 찾아 출차를 완료합니다.

### [추가 사항 7] 5. 기능 별 설계 -> 5.1 모바일 앱 설계

-> 기능 상세 설계 3번 항목 밑에 4번 항목을 추가합니다.

4. 사용자 주차 위치 세션 영속성 및 마커 오버레이 처리:
   - 사용자가 등록한 주차장 ID(parkingId) 및 주차 칸 고유 번호(spaceId)는 Firestore의 `users/{uid}/active_parking` 문서에 영속화됩니다.
   - 모바일 앱이 실행되거나 도면 뷰어(`CustomDrawingView`)가 로드될 때, 해당 데이터가 존재하면 전체 도면 좌표 리스트 중 일치하는 `spaceId`의 바운딩 박스(Bounding Box) 중심점을 계산합니다.
   - Canvas 드로잉 루프 동작 시, 해당 좌표 위에 로컬 리소스 비트맵인 차량 아이콘(`ic_my_car.png`)을 Canvas.drawBitmap()을 통해 정확히 스케일링 오버레이하여 사용자의 직관적인 출차 동선 확인을 보장합니다.

### [수정/보완 권고 사항 (문서 오류 및 품질 개선용)]

1. 번호 표기 중복 수정 (3페이지)
   - 관리자 주요기능의 타이틀 번호가 `1.2.1`로 되어 있는데, 바로 밑의 일반 사용자 주요기능 타이틀 역시 `1.2.1`로 표기되어 있습니다. 일반 사용자 주요기능의 번호를 `1.2.2`로 수정하시기 바랍니다.

2. 목차 연동 점검 (2페이지)
   - 목차 상의 주요기능 하위 넘버링도 본문의 수정사항(`1.2.2`)과 일치하도록 검토가 필요합니다.

3. 데이터 격리 정책 보완 (2.1.2 시스템 요구사항)
   - 인증 시스템 설계 내용 중 "사용자의 식별자(UID)에 따라... 철저히 격리합니다." 부분에 신규 기능인 **'사용자의 주차 위치 데이터(active_parking)'**도 격리 대상 세션 데이터에 포함된다는 문구를 명시하면 설계의 일관성이 극대화됩니다.

4. 5.1 모바일 앱 설계의 지오펜싱 플래그 오타 수정 (9페이지)
   - 5.1.3 항목의 `Intent.FLAG_ACTIVITY_REORDER_TO_FRONT` 중 `REORDER` 부분의 오타가 없는지 재점검하십시오. (명세서 작성 자체는 잘 되어 있으나, 향후 실제 안드로이드 Java 코드 반영 시 철자오류 방지를 위해 한번 더 명기해 두면 좋습니다.)
