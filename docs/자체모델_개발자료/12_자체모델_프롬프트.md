# 12-1. 자체 모델 제작용 프롬프트

아래 구분선 사이를 통째로 복사해 AI 도구(Claude 등)에 붙여 넣는다. 데이터 폴더 `handoff_1차`와 `12_자체모델_인수인계.md`를 함께 첨부하면 좋다.

---

나는 대학 졸업작품(캡스톤) 팀 "PARKIT"에서 주차장 모형의 차량을 찾는 모델을 맡았다. 지금까지 팀은 YOLO26n을 추가 학습(파인튜닝)해 왔는데, 지도교수님이 "누구나 할 수 있는 파인튜닝 말고, 성능이 조금 떨어지더라도 모델을 직접 만들어 보라. 차량만 찾으면 되니 연산량은 줄이고 신뢰도는 높일 수 있을 것"이라고 하셨다. 그래서 **YOLO 구조를 본뜬 차량 전용 탐지 모델을 PyTorch로 처음부터 직접 만들고 학습**하려고 한다. 포트폴리오로도 쓸 것이라, 내가 각 부분을 이해하고 설명할 수 있어야 한다.

## 상황

- 대상: 1:64 미니카 54대(모양은 모두 같고 도색 11종). 짙은 회색 주차장 매트 위에 세워져 있다.
- 카메라: 고정 USB 웹캠, 1920×1080. 렌즈 높이 15cm, 아래로 30° 기울여 주차칸 3~5칸을 비스듬히 본다. 카메라 위치와 차 크기가 거의 일정하다.
- 찾을 대상: `car` 한 종류. 결과는 주차칸이 찼는지 판단하는 데 쓴다.
- 실행 장치: 시연용 노트북 CPU(GPU 없음 가정). 학습은 Google Colab T4 GPU를 쓸 수 있다.

## 데이터

- 폴더 구조(YOLO 형식):
  ```
  handoff_1차/
    images/train|val|test/*.jpg
    labels/train|val|test/*.txt   ← 사진과 같은 이름. 한 줄에 "0 x중심 y중심 너비 높이" (0~1 비율)
    data.yaml
  ```
- 1차 데이터: train 27장(상자 432개), val 6장(110개), test 6장(118개). 한 장에 차가 평균 17대. 배치(차 배치) 단위로 나눠서 같은 배치가 여러 묶음에 섞여 있지 않다.
- 차 크기: 640 입력 기준 대략 66×55픽셀(중앙값). 가장 작은 것은 화면 끝에 걸린 차로 10픽셀 안팎, 가장 큰 것은 약 190×150픽셀.
- 앞으로 사진이 더 늘어난다(목표 train 150~250장). 지금은 매우 적으니 데이터 늘리기(augmentation)가 중요하다.
- **test 묶음은 마지막 평가에만 쓰고, 학습이나 설정 고르기에는 쓰지 않는다.**

## 지켜야 할 조건

1. **사전학습 가중치를 쓰지 않는다.** ultralytics의 모델 클래스나 timm 같은 미리 만든 백본도 쓰지 않는다. 층 구성, 손실 함수, 라벨 배정, 후처리(NMS)를 직접 구현한다. `torch`, `torchvision.ops`(nms, box_iou 같은 기본 함수), `opencv`, `numpy`는 써도 된다.
2. YOLO 구조를 참고하되 우리 조건에 맞게 줄인다. 예를 들어:
   - 클래스가 하나이고 차 크기가 거의 일정하니, YOLO의 3단계(stride 8/16/32) 출력이 다 필요한지 따져 보고 1~2단계로 줄이는 것을 검토한다.
   - 앵커 없는(anchor-free) 방식과 분리된 헤드(decoupled head)를 기본으로 하되, 더 단순한 방식이 낫다면 근거와 함께 제안한다.
   - 백본은 CSP 계열이나 depthwise separable conv처럼 가벼운 블록으로, 폭과 깊이를 설정값으로 바꿀 수 있게 한다.
3. 입력은 640(긴 변 기준, 비율 유지 letterbox). 출력은 원본 사진 픽셀 좌표의 `x1, y1, x2, y2`와 신뢰도 목록이다.
4. 목표: test에서 IoU 0.5 기준 Recall·Precision 각 95% 이상, 노트북 CPU에서 YOLO26n(프레임당 약 0.05초)보다 빠르거나 비슷하게. 파라미터 수와 GFLOPs도 YOLO26n보다 작게 하는 것이 목표다.

## 만들 것 (순서대로, 단계마다 멈추고 결과를 확인한 뒤 다음으로)

1. **데이터 로더**: 사진과 라벨을 읽고 letterbox, 데이터 늘리기(좌우 뒤집기, 밝기·채도·색조 변경, 크기·위치 이동, mosaic)를 적용. 상자가 제대로 따라가는지 그림으로 저장해 확인하는 코드 포함.
2. **모델**: 백본·넥·헤드를 나눈 코드. 임의 입력으로 출력 모양을 확인하고, 파라미터 수와 GFLOPs를 출력.
3. **라벨 배정과 손실**: 어떤 출력 위치가 어떤 차를 맡을지 정하는 방법(예: center sampling, task-aligned assigner)과 손실(상자 IoU 계열 + 신뢰도 BCE 등). 왜 그렇게 골랐는지 설명.
4. **과적합 시험**: 사진 2장으로만 학습해 손실이 거의 0이 되고 상자가 정확히 맞는지 먼저 확인(코드에 버그가 없는지 보는 단계).
5. **학습**: Colab에서 돌릴 수 있는 학습 스크립트. 학습 곡선과 val 점수를 저장하고, val 점수가 가장 좋은 가중치를 `best.pt`로 저장.
6. **평가**: test 묶음에서 Precision, Recall, mAP50, 신뢰도 0.25에서 놓친 차·헛잡은 것 개수. 예측 상자를 그린 사진도 저장.
7. **속도 측정**: CPU에서 640 입력 1장당 평균 시간(앞 10번은 빼고 100번 평균). 같은 방법으로 YOLO26n도 재서 나란히 표로.
8. **바꿔 끼우기용 함수**: `detect(frame) -> [{"box": [x1, y1, x2, y2], "conf": 0.93}, ...]` 형태로 웹캠 프레임(BGR numpy 배열)을 받아 결과를 돌려주는 함수.

## 설명 방식

- 코드마다 각 부분이 YOLO의 어느 부분에 해당하고, 우리 조건 때문에 무엇을 바꿨는지 짧게 설명해 줘.
- 데이터가 적어서 생길 수 있는 문제(과적합 등)와 그 대응을 알려 줘.
- 발표에서 "직접 설계한 부분"으로 설명할 수 있는 포인트를 마지막에 정리해 줘.
