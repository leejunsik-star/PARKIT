# PARKIT Tiny 초기 모델 실행 결과 (2026-10-27)

## 제공하는 모델

`runs/train/best.pt`는 사전학습 없이 PARKIT train 27장으로 학습한 차량 단일 클래스 모델입니다. 폭 16, 입력 640×640, 파라미터 597,562개입니다. 합성곱 기준 3.959 GFLOPs이며 BN·활성화·후처리는 이 연산량에 포함하지 않습니다.

100 epoch 실행을 시작했으나 90 epoch 완료 후 다음 체크포인트 저장에서 `File ... cannot be opened` 오류가 발생했습니다. 단일 오류의 근본 원인은 확인하지 못했습니다. 저장 방식은 Python 파일 객체를 통해 임시 파일에 완전히 쓴 뒤 교체하도록 보완했습니다. 기존 best/last 가중치의 로딩·저장·재로딩 동일성 검사와 별도 1 epoch 학습 저장 검사를 통과했습니다. 이 결과의 실제 완료 학습량은 **90 epoch**이며 100 epoch 완료로 보고하지 않습니다. last.pt는 90회차, best.pt는 val AP50 기준 최고였던 75회차입니다.

## 평가 범위

train: 27장 / 432개 상자. val: 6장 / 110개 상자. test: 최종 평가를 위해 이번 실행에서 로드하거나 평가하지 않았습니다. 데이터 목록과 수량을 확인한 것 외에 test로 모델·임계값을 선택하지 않았습니다. 아래 결과는 전부 **val 결과**이며 독립적인 test 성능이 아닙니다.

| 조건 | Precision | Recall | 오탐 | 누락 |
|---|---:|---:|---:|---:|
| 신뢰도 0.25, NMS IoU 0.5 | 66.06% | 99.09% | 56 | 1 |
| 신뢰도 0.45, NMS IoU 0.5 | 95.88% | 84.55% | 4 | 17 |

AP50은 **96.57%**입니다. 단일 클래스이므로 mAP50과 같습니다. AP50은 여러 신뢰도 수준의 순위를 평가하며, 신뢰도 0.25의 Precision과 동일한 지표가 아닙니다. 자체 101점 보간 평가 구현으로 산출했으며 COCO 전체 평가기와 동일함을 주장하지 않습니다.

임계값 0.45는 0.25, 0.35, …, 0.95 후보 중 val의 F1 최고값으로 선택했습니다. 0.35에서는 Precision 88.50%, Recall 90.91%로 다른 균형을 보였습니다. 임계값을 높이면 오탐을 줄이는 대신 놓치는 차량이 늘어납니다. 목적에 맞는 선택과 추가 데이터 검증이 필요합니다. **Precision과 Recall 각각 95%라는 목표는 아직 달성하지 않았습니다.**

## 속도

CPU 4스레드, 640 입력, 첫 번째 val 이미지에 대해 10회 예열 후 100회 평균 **23.64ms**, p95 **27.76ms**입니다. 모델 순전파·상자 디코딩·NMS를 포함하고 이미지 읽기·리사이즈·BGR 변환은 제외합니다. 한 이미지 반복 측정이므로 전체 카메라 시스템의 지연이나 처리량을 보장하지 않습니다. 동일 기기·환경의 YOLO 비교는 아직 수행하지 않았습니다.

## 실행 검증

- letterbox 상자 좌표 변환과 역변환.
- 출력 크기, 양수 폭·높이, 양성 정답 배정, 손실의 유한성.
- 상자 헤드에 실제 역전파 기울기가 생기는지 확인.
- 빈 정답 처리, 알려진 상자에 대한 IoU 및 NMS.
- 정답·오탐·누락이 알려진 합성 사례의 Precision·Recall·AP50.
- 실제 BGR 프레임을 받는 Detector의 원본 1920×1080 좌표 복원.
- 학습 이미지 2장(차량 44개) 과적합: Precision·Recall·AP50 모두 100%. 이는 구현 검사이며 일반화 성능이 아닙니다.
- 학습 증강 12장과 val 예측 이미지의 시각적 확인.
- 가중치 저장·재로딩 및 보완된 저장 경로로 1 epoch 학습 완료.

## 다음 개선의 우선순위

1. 빈 매트와 다양한 배치·조명·가림·경계 차량 사진 추가.
2. 작은 차량의 격자 배정 누락과 저신뢰 중복 탐지를 train/val에서 분석.
3. val에서 구조·신뢰도 설정을 고정한 후, 남겨둔 test를 최종 평가.
4. 같은 입력·스레드·장치·전후처리 범위로 YOLO와 속도·정확도 비교.

현재 결과는 **직접 구현하고 실제 학습까지 수행한 초기 모델**입니다. 실제 주차 점유 판정, 접지점의 정확성, 다중 카메라 호모그래피, Firebase와 앱 연결은 이 모델 이후의 별도 작업입니다.
