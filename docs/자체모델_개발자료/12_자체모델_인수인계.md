## 2. 1차 데이터 현황 (2026-10-26 확인)

- 사진 39장, 모두 1920×1080 JPG. 상자 660개, 클래스는 `car`(번호 0) 하나. 라벨은 YOLO 형식(`클래스 x중심 y중심 너비 높이`, 0~1 비율).
- 모든 사진에 라벨 파일이 있고, 라벨만 있고 사진이 없는 경우도 없다.
- 이름 규칙: `A_1_0001.jpg` = 묶음 A, 배치 1, 그 배치의 1번째 사진. 배치마다 2~3장이다(A 7배치, B 6배치, 모두 13배치).
- 상자 크기(사진 대비 비율): 너비 0.009~0.30(중앙값 0.10), 높이 0.03~0.41(중앙값 0.15). 640으로 줄여 넣으면 차 한 대가 대략 66×55픽셀이고, 가장 작은 것(화면 끝에 걸린 차)은 10픽셀 안팎이다.

### 나눈 방법

같은 배치의 사진은 거의 같으므로 **배치 단위로** 나눴다(10 문서 4절).

| 묶음 | 배치 | 사진 | 상자 |
|---|---|---|---|
| train | A_1~A_5, B_1~B_4 | 27 | 432 |
| val | A_6, B_5 | 6 | 110 |
| test | A_7, B_6 | 6 | 118 |

- A와 B가 무엇(촬영자, 카메라 위치 등)을 뜻하는지에 따라 나누는 방법을 바꿀 수 있다. 원래 폴더(`raw\1차데이터`, `labels_1차`)는 그대로 두었으니 다시 나눠도 된다.
- **test 6장은 학습과 설정 고르기에 절대 쓰지 않는다.** 마지막 비교 때만 쓴다.

### 부족한 점

- **양이 매우 적다.** 처음부터 학습하는 모델에 39장은 부족하다. 1차 데이터는 "코드가 돌아가고 학습이 되는지" 확인하는 용도로 보고, 성능 비교는 2차 이후 데이터가 모인 뒤에 한다.
- **차 없는 빈 매트 사진이 없다.** 칸 선·X 표시·글자를 차로 잘못 잡는 것을 막으려면 다음 촬영 때 카메라 위치마다 몇 장씩 넣는다(10 문서 4절).
- test가 6장(118대)이라 1~2대 차이로도 점수가 몇 %씩 흔들린다.

## 3. 목표 조건

| 항목 | 기준 |
|---|---|
| 찾을 대상 | `car` 하나 |
| 입력 | 웹캠 1920×1080 → 모델 입력 640(긴 변 기준, 비율 유지) |
| 정확도 목표 | test에서 Recall·Precision 각 95% 이상 (10 문서 8절) |
| 속도 | 시연 노트북 CPU에서 YOLO26n(클라우드 CPU 기준 프레임당 약 0.05초) 이하 |
| 함께 잴 것 | 파라미터 수, 연산량(GFLOPs), CPU 프레임당 시간 |
| 출력 | 사진 픽셀 좌표 상자 `x1, y1, x2, y2` + 신뢰도. `edge/yolo_detection/detector.py`의 `Detection`과 같은 형태로 내면 접지점 계산(`ground_point.py`)에 바로 연결된다 |

## 4. 비교 방법

같은 test 묶음, 같은 입력 크기(640), 같은 PC에서 아래를 나란히 잰다.

| 모델 | 뜻 |
|---|---|
| YOLO26n 파인튜닝 | 사전학습 + 우리 데이터 (우리 쪽에서 준비) |
| YOLO26n 구조, 사전학습 없이 | `yolo detect train model=yolo26n.yaml pretrained=False ...` 같은 구조를 우리 데이터로만 학습 |
| 자체 모델 | 동료가 만든 모델, 우리 데이터로만 학습 |

- 두 번째 줄이 있으면, 자체 모델과의 차이가 **구조** 때문인지 **사전학습** 때문인지 설명할 수 있다. 발표에서 "같은 조건이면 우리 모델이 더 가볍고 비슷하게 잡는다"를 보여 주는 근거가 된다.
- 평가 숫자는 IoU 0.5 기준 Precision, Recall, mAP50, 그리고 신뢰도 0.25에서의 놓친 차·헛잡은 것 개수.
