# 아이폰 2대 + 웹캠 1~2대 혼합 촬영 (2026-11-10)

## 사용 순서

1. Windows에서 DroidCam으로 아이폰 두 대를 연결한다. 프로그램에 서로 다른 입력으로 보여야 한다. 같은 가상 카메라의 화면만 전환되는 상태는 두 대 동시 입력이 아니다.
2. `calibrate.py` 또는 `calibrate_v2.py`를 실행한다. CAM-1~CAM-4가 기본 목록에 나온다. 실제 영상 미리보기로 각 장치를 구분해 번호를 지정한다(0~7 검색).
3. 각 카메라를 하나씩 열고 오른쪽 **입력 → 촬영 방식**을 고른다.
   - 아이폰: **상부 촬영 · 박스 정중앙** (`contact_mode: center`).
   - 사선 웹캠: **사선 촬영 · 기존 바닥 접점** (`contact_mode: ground`).
4. 각 장치의 설치 위치·렌즈·배율·영상 방향·해상도를 고정하고 기준점과 감시 칸을 보정한 후 저장(S)한다. 보정은 카메라별로 수행한다. 같은 이름을 재사용하면 해당 카메라의 설정을 수정하는 것이므로 장치마다 이름을 구분한다.
5. `occupancy.py --web`를 실행하고 보정한 카메라 3대 또는 4대에 체크한다. 시작 창의 촬영 방식과 보정 경로/날짜를 확인한다. 사용하지 않는 CAM-4는 체크하지 않는다.
6. 관리자 화면은 3~4대를 고르면 2×2로 표시한다. 2D 지도는 `http://127.0.0.1:8765/`에서 확인한다.

Windows PowerShell, PARKIT 루트:
```powershell
.venv-gui\Scripts\python.exe docs\도구\occupancy_v7\calibrate_v2.py
.venv-gui\Scripts\python.exe docs\도구\occupancy_v7\occupancy.py --web
```
Mac, PARKIT 루트:
```sh
.venv-gui/bin/python docs/도구/occupancy_v7/calibrate_v2.py
.venv-gui/bin/python docs/도구/occupancy_v7/occupancy.py --web
```

일반 보정은 위 명령에서 `calibrate_v2.py`를 `calibrate.py`로 바꾼다.
DroidCam이 웹캠 대신 직접 영상 URL을 제공하는 구성은 기존 `--cam CAM-1 --source 실제영상주소` 입력을 사용할 수 있다. 주소는 앱이 제공하는 실제 영상 스트림이어야 하며 웹페이지 주소와 다르다. 앱별 다중 연결 가능 여부는 이번에 검증하지 않았다.

## 저장 및 호환

- 일반 보정: `docs/도구/occupancy_v7/config/cam_CAM-N.json`.
- v2 보정: `docs/도구/occupancy_v7/config/v2/cam_CAM-N.json`.
- JSON의 `contact_mode`에 촬영 방식을 저장한다. 키 없는 이전 파일은 ground로 동작한다.
- 판정 시작 창은 일반/v2에 같은 이름이 있으면 보정 파일의 저장 날짜가 최근인 하나를 표시한다. 명시적으로 `--run`을 주면 해당 실행 설정의 경로를 그대로 사용한다.
- 기존 실제 보정 파일과 영상 소스는 이번 코드 작업에서 수정하지 않았다. CAM-3/4의 가짜 보정 파일도 만들지 않았다.
- DroidCam 출력 영상을 그대로 보정·추론에 사용하며 추가 렌즈 왜곡 보정은 적용하지 않는다. 사용자가 기존 출력으로 보정 가능함을 실험했다는 조건을 따른다.

## 처리 구조

카메라별 입력 → 탐지 박스 → 촬영 방식별 위치/점유 판정 → 공통 매트 좌표 → 시간·속도 gating → 카메라별 Hungarian 매칭 → Global ID → 웹 지도.

- 기존 사선 판정: `parkit_judge.py`의 기존 경로 유지.
- 상부 판정: `camera_contact.py`의 별도 경로. 박스 중앙을 호모그래피로 변환한다. 중심이 주차면 inner 안에 있으면 해당 칸의 점유 관측으로 보낸다.
- 상부 박스가 화면에 잘리거나 서로 겹치면 정확한 중심을 알 수 없으므로 추적 관측을 보류한다. 다른 카메라/기존 추적의 유효 시간으로 유지한다.
- 상부 박스가 옆 칸까지 걸치면 그 칸은 '모름'(None)으로 보류한다. 박스의 빈 모서리를 실제 차체로 간주해 두 칸 점유를 확정하지 않는다. 상부 촬영의 정확한 다중 칸 점유에는 별도 차체 방향/발자국 추정이 필요하다.
- 하나의 카메라 안에서는 일대일 할당, 서로 다른 카메라 사이에서는 같은 Global ID에 여러 관측을 연결한다. 기존 구조를 유지하며 동시 관측의 카메라 간 오차를 이동으로 잘못 판단하던 gating을 수정했다.
- 같은 카메라의 이전 관측으로 이동량을 검증한다. 새 카메라의 연결은 별도의 cross_camera_radius_cm/window 범위로 제한한다. 애매한 연결은 기존 UNCERTAIN 처리를 유지한다.
- 상부 촬영이 섞이면 사선 주차 차량의 예상 접점과 칸 중심 차이를 이용해 추적 위치를 중심 쪽으로 근사 보정한다. 기존 통로 접점 보정은 사선에만 적용하고 상부 중앙에는 적용하지 않는다. 주차면 상태 Tracker와 merge_obs는 수정하지 않았다.
- 완전히 동시인 관측은 기존 평균 처리, 시각이 다르면 각각의 관측 시각으로 예측·갱신한다. 단순히 모든 점을 같은 시점으로 평균내지 않는다.

## 수정 파일

| 파일 (occupancy_v7 아래) | 역할 |
|---|---|
| calibrate.py | CAM-1~4 기본 제공, 0~7 입력 검색, 촬영 방식 선택/저장/재로드 |
| calibrate_v2.py | 일반 보정 가져오기에도 촬영 방식 보존; 상속한 UI/저장 경로 사용 |
| occupancy.py | 4대 표시, 촬영 방식 표시, 최신 일반/v2 보정 선택, 혼합 시점 추적 설정 |
| parkit_geom.py | 카메라 촬영 방식 읽기·검증 |
| parkit_judge.py | 상부 촬영만 새 판정 경로로 분기 |
| tracking_bridge.py | 상부 중앙 보존, 사선 주차 접점의 중심 근사 보정, 불확실 관측 제외 |
| vehicle_tracker.py | 같은 카메라 이동량 검증과 카메라 간 오차 gating 분리 |

신규: `camera_contact.py`, `test_multi_camera.py`, 이 설명 문서.
다른 컴퓨터로 옮길 때 코드 변경분을 함께 반영해야 한다. 다른 컴퓨터의 실제 보정 JSON을 이 컴퓨터의 JSON으로 덮어쓰지 않는다. 개인 보정 JSON과 확인 사진은 PR에 포함하지 않는다.

## 제한 및 실제 시연 확인

- 이 구현은 거리·시간·이동 예측 기반이다. 가까이 붙거나 교차하는 같은 모양 차량을 항상 구별하는 Re-ID 보장은 없다.
- 상부 박스 중앙은 차량 지붕의 영상 위치를 바닥으로 투영한 근사다. 완전 수직이 아니거나 높이 차이가 있으면 오차가 생긴다. 사선 중심 보정도 설정된 차량 크기/카메라 자세를 이용한 근사다.
- 현재 라이브 입력 시각은 PC 수신 시각이다. DroidCam 내부 버퍼/네트워크 지연을 실제 촬영 시각으로 복원하지 못한다. 장치 간 지연이 크면 안정적인 통합이 어려우므로 같은 움직임으로 영상 지연을 비교해야 한다.
- 모델이 상부 미니카를 놓치면 상부 시점 데이터 학습이 필요하다. 이번 작업은 모델을 재학습하지 않았다.
- 실제 Windows + 아이폰 2대 + 웹캠 1~2대는 여기서 실행하지 못했다. Mac GUI는 합성 이미지/가짜 목록으로 생성 및 모드 전환을 검사했다.
- 실제 시연에서는 각 카메라로 같은 정지 차량의 매트 좌표를 비교하고, 이동·회전·카메라 전환·3~4대 동시 관측·한 카메라 끊김을 확인해야 한다.
- GUI에서 선택한 3~4대는 한 모델을 공유해 순차 추론한다. 실제 FPS는 장비 성능과 분석 간격에 따라 달라진다.
