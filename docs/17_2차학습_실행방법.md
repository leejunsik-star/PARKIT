# 2차 학습 실행 방법 (2026-10-30)

15 문서의 비교 실험(M1~M5)을 실제로 돌리는 순서다. 나누기와 채점은 PC(CPU)에서 하고, 학습은 코랩(T4)에서 한다.

## 0. 만든 파일

| 위치 | 내용 |
|---|---|
| `docs\도구\make_split_2차.py` | 원본(data_*, labels_*)을 복사해서 나누고, 목록·yaml·압축·handoff_2차를 만들고 확인한다 |
| `docs\도구\coco_negatives.py` | `--exclude` 옵션 추가(뽑을 때 뺄 COCO 번호). 나머지 동작은 그대로다 |
| `dataset\data_neg_coco_test\` | COCO 시험용 30장(`--seed 2 --n 30 --exclude ..\..\dataset\data_neg_coco`). 학습용 seed 1과 겹치는 번호는 없다 |
| `dataset\split_2차\` | 나눈 사진·라벨, `train_M1~M5.txt`, `data_M1~M5.yaml`, `test_T1~T5.txt/.yaml`, `확인결과.txt` |

## 1. 나누기 (이미 했음)

배치째로 나눴다. 같은 배치가 두 나누기에 걸치지 않는다.

| 출처 | train | val | test (시험 세트) |
|---|---|---|---|
| 1차 집 | A_1~A_5, B_1~B_4 (27장) | A_6, B_5 (6장) | A_7, B_6 (6장) → T1 |
| 2차 학교 | s1~s6 (36장) | s7 (6장) | s8, s9 (12장) → T2 |
| 4차 차 적음 | little_car_1, _3 (14장) | little_car_2 (5장) | little_car_4 (7장) → T3 |
| 3차 빈 매트 | 후보 x_0001~0021 (21장) | x_0022~0024 (3장) | x_0025~0030 (6장) → T4 |
| COCO | 후보 seed 1 (60장) | 없음 | seed 2 새로 30장 → T5 |
| 합계 | 158장 | 20장 | 61장 |

모델별 train (val 20장, test는 모두 같다):

| 모델 | train 구성 | 장 수 | 차 없는 사진 |
|---|---|---|---|
| M1 | 1차 | 27 | 0 |
| M2 | 1차 + 2차 | 63 | 0 |
| M3 | 1차 + 2차 + 4차 | 77 | 0 |
| M4 | M3 + 3차 8장 + COCO 7장 | 92 | 15 (16%) |
| M5 | M3 + 3차 21장 + COCO 60장 | 158 | 81 (51%) |

M4의 차 없는 사진은 seed 42로 고정해서, 후보 목록을 8칸(3차)·7칸(COCO)으로 나눠 칸마다 한 장씩 골랐다(연달아 찍은 3차가 한쪽으로 몰리지 않게).
- 3차: x_0001, 0003, 0007, 0008, 0011, 0014, 0018, 0019
- COCO: 030785, 140439, 189451, 294350, 449190, 507081, 551439

사진을 모델마다 복사하지 않았다. `images\train`에 train 후보 158장이 모두 있고, `train_M*.txt`가 그중 어떤 사진을 쓸지 정한다.

yaml에는 `path`를 쓰지 않았다. ultralytics는 `path`가 없으면 yaml이 있는 폴더를 기준으로 경로를 찾는다. 그래서 같은 파일을 PC와 코랩에서 그대로 쓴다. (`path: .`라고 쓰면 yaml 위치가 아니라 **실행한 폴더**가 기준이 되어서, 다른 폴더에서 실행하면 사진을 못 찾는다.)

라벨을 고쳤거나 사진을 더하면 다시 만든다(`split_2차`, `split_2차.zip`, `handoff_2차`만 지우고 다시 만든다. 원본은 건드리지 않는다).

```
cd docs\도구
python make_split_2차.py --overwrite
```

확인만 하려면 `python make_split_2차.py --check`. 결과는 `split_2차\확인결과.txt`에도 남는다.

## 2. 코랩에서 학습

1. `dataset\split_2차.zip`을 구글 드라이브 **내 드라이브** 맨 위에 올린다.
2. 드라이브에서 `docs\도구\colab_train_2차.ipynb`를 올려 **Google Colaboratory로 열기**(또는 colab.research.google.com → 파일 → 노트 업로드).
3. **런타임 → 런타임 유형 변경 → T4 GPU** → 저장.
4. **런타임 → 모두 실행**.

- 설정은 지난 학습과 같다: `yolo26n.pt, imgsz=640, epochs=100, batch=16, hsv_h=0.05` (+ 모델끼리 비교가 공정하게 `seed=0, deterministic=True`).
- 모델 하나가 끝날 때마다 드라이브 `parkit_runs_2차\M1` ~ `M5`에 `best.pt`, `results.png`, `results.csv`, `args.yaml`을 저장한다.
- **연결이 끊기면** 노트북을 처음부터 다시 실행한다. 드라이브에 `best.pt`가 있는 모델은 건너뛰고, 중간에 끊긴 모델만 처음부터 다시 학습한다.
- 한 모델만 다시 하려면 드라이브의 그 모델 폴더를 지우고 실행한다. 일부만 돌리려면 2번 셀의 `MODELS`를 고친다.
- 예상 시간(추정): 다섯 모델 합쳐 1시간 안팎.

## 3. PC에서 채점

1. 드라이브의 `parkit_runs_2차`를 내려받아 `M1\best.pt` ~ `M5\best.pt`를 `docs\도구\models\M1.pt` ~ `M5.pt`로 이름을 바꿔 둔다(표에는 파일 이름이 모델 이름으로 들어간다).
2. 실행한다. 인자가 없으면 기존 `best.pt`와 `models\*.pt`를 모두 채점한다.

```
cd docs\도구
python eval_2차.py
```

- 고른 모델만: `python eval_2차.py best.pt models\M4.pt`
- T4·T5 신뢰도 기준 바꾸기: `--conf 0.4` (기본 0.25)
- 결과: `docs\도구\eval_2차_결과\eval_2차.csv`, `eval_2차.md`
- 시간: CPU에서 모델 하나에 10초 안팎.

숫자 보는 법:
- T1~T3: `model.val(split=test)`의 Precision, Recall, mAP50.
- T4·T5: 신뢰도 기준 이상인 상자는 모두 오탐이다. "오탐 사진"은 상자가 하나라도 나온 사진 비율.

주의:
- **best.pt의 T2·T3 점수는 실제보다 좋게 나왔을 수 있다.** 2차·4차 라벨은 best.pt가 만든 자동 라벨을 사람이 고친 것이라, 사람이 못 고친 best.pt의 실수는 정답으로 남아 best.pt에 유리하다(15 문서 2절). M1~M5끼리 비교할 때는 이 문제가 같다.
