# 41. 평면도 각도와 감시 칸 끌기 → occupancy_v6 (2026-11-07)

보정 도구와 판정 프로그램의 화면 조작 두 가지를 고쳤다. 판정 결과는 바뀌지 않는다.

1. **감시 칸 끌기:** 보정 도구(`calibrate.py`, `calibrate_v2.py`)의 ② 감시 칸 단계다. 왼쪽 클릭·끌기로 켜고, 오른쪽 클릭·끌기로 끈다.
2. **평면도 각도:** 보정 도구와 판정 프로그램(`occupancy.py`)의 오른쪽 평면도를 0~359° 돌린다. [카메라 시점]을 누르면 카메라 화면과 같은 방향으로 본다.

`occupancy_v6`에서 바로 고쳤다(사용자 결정). v5는 그대로 두었다. 커밋하지 않았다.

## 1. 감시 칸 끌기

| 동작 | 결과 |
|---|---|
| 왼쪽 클릭 | 그 칸 감시 켜기 |
| 오른쪽 클릭 (맥은 2번 버튼도) | 그 칸 감시 끄기 |
| 왼쪽 누른 채 끌기 | 켜기. "지나간 칸"이면 마우스가 지나간 칸 모두, "네모 안 칸"이면 끌어서 그린 네모 안에 가운데가 든 칸 모두 |
| 오른쪽 누른 채 끌기 | 끄기 (방식은 같음) |

- 카메라 화면과 평면도 모두에서 된다. 평면도를 돌려도 된다.
- **끌기 방식**은 ② 감시 칸 틀의 [지나간 칸 / 네모 안 칸]에서 고른다. 처음 방식은 `run.json`의 `display.monitor_drag`(`"paint"` 또는 `"rect"`)다.
  - 지나간 칸: 비스듬히 보이는 카메라 화면에서 원하는 칸만 고르기 쉽다. 빠르게 끌어도 칸을 건너뛰지 않게, 지난 점과 지금 점 사이를 화면 3픽셀 간격으로 본다.
  - 네모 안 칸: 평면도에서 한 줄을 통째로 고를 때 빠르다. 그리는 동안 네모가 보인다(켜기 초록, 끄기 빨강).
- **예전과 다른 점:** 예전에는 클릭할 때마다 켜고 끄기를 오갔다. 이제 왼쪽은 켜기만, 오른쪽은 끄기만 한다. 이미 켜진 칸을 왼쪽으로 누르면 "바뀐 칸이 없습니다"라고 나온다.
- 끄는 동안에는 보정을 다시 계산하지 않고, 마우스를 놓을 때 한 번만 계산한다. 그래서 여러 칸을 끌어도 느려지지 않는다. 바뀐 칸은 아래 안내에 `감시 켬: 10~12 (3칸)`처럼 나온다.
- ①·③·④ 단계의 평면도 왼쪽 클릭은 예전처럼 칸 고르기다. 오른쪽 클릭은 아무것도 하지 않는다.
- `calibrate_v2.py`는 `calibrate.py`의 화면과 마우스 처리를 물려받아 쓰므로 같이 바뀌었다.

## 2. 평면도 각도

평면도 아래에 각도 막대가 있다.

```
도면 각도 [━━━━━━━●━━━━━━] 180°
[0°] [↻90°] [카메라 시점]          ← 판정 프로그램은 [CAM-1 시점] [CAM-2 시점]
```

| 조작 | 하는 일 |
|---|---|
| 슬라이더 | 0~359°, 1° 단위. 시계 방향으로 돌린다 |
| [0°] | 처음 방향 (15~27번 줄이 위) |
| [↻90°] | 지금 각도에서 90° 더 |
| [카메라 시점] | 카메라가 **아래에서 위를 보게** 돌린다. 카메라 화면처럼 가까운 칸이 아래, 카메라 오른쪽이 화면 오른쪽이다 |

- **카메라 시점 각도**는 보정 파일의 카메라 자세(렌즈 위치, 보는 방향 `yaw_deg`)로 구한다: 각도 = (-90° − yaw) mod 360.
  - 매트 위쪽(15~27번 줄 밖)에서 아래를 보는 카메라는 180°다.
  - 지금 CAM-1처럼 매트 아래쪽(42~56번 줄 밖)에서 위를 보는 카메라는 0°에 가깝다(11-07 보정 359.6°).
  - 대각선 카메라는 그 사이의 비스듬한 각도가 된다.
- [카메라 시점]을 누르면 각도 옆에 `*`가 붙는다. 이 동안 보정을 고쳐 카메라 자세가 바뀌면 각도도 따라 바뀐다. 슬라이더, [0°], [↻90°]를 쓰면 따라가기가 꺼진다.
- 카메라 자세가 아직 없으면(기준점 4개 미만) 알림만 나오고 돌리지 않는다.
- 칸 번호와 카메라 이름 글자는 돌리지 않고 늘 똑바로 쓴다.
- 0°에서는 예전과 같은 크기·배율로 그린다. 돌리면 같은 평면도 칸 안에 꽉 차게 배율을 맞춘다. 90°처럼 세로로 긴 모양이 되면 조금 작아진다.
- **카메라 표시:** 예전에는 카메라가 매트 아래쪽 밖에 있으면 그림 밖이라 안 보였다(지금 CAM-1, y 68.9). 이제는 노란 삼각형을 평면도 가장자리에 붙여 그리고, 매트 가운데를 가리키게 했다.
- **판정 프로그램:** 시연 화면(D 키)과 화면 저장(S)도 같은 각도로 그린다. 카메라 2대면 [CAM-1 시점], [CAM-2 시점]이 따로 있다.
- **처음 각도:** `run.json`의 `display.plan_angle`에 숫자(도)를 적거나, `"camera"`를 적으면 첫 카메라 시점으로 시작한다. 기본은 0이다. 창에서 바꾼 각도는 저장하지 않는다.

### 다른 방법도 생각해 본 것

- **90° 단위만:** 매트가 늘 화면을 꽉 채우지만, 대각선 카메라에는 맞지 않는다. [↻90°] 버튼으로 남겼다.
- **카메라 원근 그대로(화면처럼 사다리꼴):** 카메라 화면에 이미 칸 선이 겹쳐 보이므로 같은 그림이 하나 더 생길 뿐이라 넣지 않았다.
- **지금 고른 방식(자유 각도 + 카메라 시점 버튼)**이면, 보통은 [카메라 시점] 한 번으로 카메라 화면과 같은 방향이 된다. 필요할 때만 슬라이더로 맞추면 된다.

## 4. 시험

- **평면도 그림:** 각도 0°에서 고치기 전과 그림을 비교했다. 달라진 픽셀은 카메라 표시(일부러 바꿈)와 매트 오른쪽 끝 1픽셀 줄뿐이다.
- **보정 도구 창 시험** (v1, v2 각각 20 / 20): 저장된 CAM-1 보정과 사진으로 창을 띄우고, 마우스 처리 함수에 가짜 이벤트를 넣었다. 보정 파일은 저장하지 않았고, 바뀌지 않았음을 확인했다.
  - 카메라 화면에서 오른쪽으로 끌어 3칸 끄기, 왼쪽 네모로 다시 켜기를 확인했다. 왼쪽 클릭 두 번은 켜진 채 그대로였다.
  - 평면도 0°, 90°, 180°, 37°, 300°에서 56칸 가운데를 누르면 모두 제 칸이고, 그림 밖으로 나가는 칸이 없었다.
  - 평면도 180°에서 오른쪽 끌기로 끄기(사이 칸 포함)와 왼쪽 네모로 켜기를 확인했다.
  - ① 단계 평면도의 왼쪽 클릭은 칸 고르기, 오른쪽 클릭은 감시 칸을 바꾸지 않았다.
  - [카메라 시점]은 카메라가 매트 가운데보다 아래에 오게 돌렸다.
- **판정 프로그램 창 시험** (8 / 8): `test_pipeline.py`의 합성 영상과 정답 상자를 썼다(웹캠 안 씀).
  - 0°, 90°, 180°, 245°에서 56칸 클릭이 모두 제 칸이었다.
  - [CAM-1 시점], [CAM-2 시점]은 각각 180°가 나왔다(합성 카메라가 매트 위쪽에서 아래를 봄).
  - 시연 화면도 돌린 도면으로 열렸다.
- **기존 시험:**
  - test_geometry 45/45, test_pipeline 33/33, test_aisle_contact_shift 16/16
  - test_vehicle_tracker, test_tracking_integration, test_tracking_replay 통과
  - test_autoref 12/13(원래 있던 대각선 실패)
- 실제 웹캠과 맥에서는 확인하지 않았다. 맥은 오른쪽 클릭이 2번 버튼이라 2번·3번 버튼을 모두 연결해 두었다.
