# 칸마다 잘라서 분류하는 방식 (2026-10-31)

22 문서의 기본안(바닥 접점)과 비교하려고 정리했다. 연구에서 많이 쓰는 방식이다. PKLot(브라질 UFPR, 칸 이미지 약 70만 장)과 CNRPark-EXT(이탈리아, 작은 CNN "mAlexNet")가 대표적인 예다.

## 1. 어떻게 하나

```
웹캠 프레임
 → 칸마다 미리 정해 둔 영역(ROI)을 잘라냄 (감시 칸 15개 → 작은 사진 15장)
 → 크기를 맞춤 (예: 128×128)
 → 분류 모델: "빈 칸" / "찬 칸" 확률
 → 시간 거르기 (입차 3초, 출차 5초) → EMPTY / OCCUPIED
```

차를 찾는 **탐지 모델**이 아니라, 사진 한 장이 어느 쪽인지만 답하는 **분류 모델**을 쓴다. 칸 하나에 답이 하나라서 출력이 곧 칸 상태다.

## 2. 만드는 순서

1. **칸 영역 정하기.** 카메라마다 칸 네 모서리를 화면에서 찍는다(또는 22 문서의 호모그래피로 계산한다). 비스듬히 보는 카메라에서는 차가 칸 바닥보다 위로 솟아 보이므로, 바닥 사각형을 차 높이(약 2.5cm)만큼 위로 늘려 자른다.
2. **자르는 방법.**
   - 그냥 자르기: 칸을 감싸는 직사각형으로 자른다. 쉽지만 옆 칸이 같이 들어간다.
   - 펴서 자르기: `warpPerspective`로 칸을 정면에서 본 직사각형으로 편다. 칸마다 크기와 모양이 같아져 학습이 쉬워진다.
3. **데이터 모으기.** 라벨은 상자를 그리지 않고 폴더로 나누기만 하면 된다(`empty/`, `occupied/`). 사진 한 장에서 감시 칸 15개쯤이 나오므로 금방 모인다. 예를 들어 카메라 2대 × 15칸 × 100장이면 칸 사진 3,000장이다.
   - 빈 칸에 지우개·병뚜껑을 둔 사진은 `empty`, 두 칸에 걸친 차는 두 칸 모두 `occupied`로 넣는다.
   - 조명, 차 종류, 차가 칸 안에서 놓인 위치를 바꿔 가며 찍는다.
4. **자동 라벨.** 고정한 카메라로 찍은 사진에 M8과 22 문서의 바닥 접점 판정을 돌리면 칸 사진의 라벨을 먼저 붙일 수 있다. 사람은 폴더를 훑어보며 틀린 것만 옮긴다.
5. **학습.** Ultralytics의 분류 모델(`yolo26n-cls.pt`, `task=classify`)을 쓰면 지금과 같은 방법으로 코랩에서 학습한다. 사진이 작아(96~128) 학습도 빠르다.
6. **실행.** 칸 12개를 한 번에 넣어도 CPU에서 충분히 빠르다(추정).

## 3. 장점

- **라벨이 쉽다.** 상자를 그릴 필요 없이 폴더로만 나눈다.
- **탐지가 놓쳐도 영향이 적다.** 차 일부만 보여도 "칸이 차 보인다"는 판단은 할 수 있다.
- **걸친 차(S8)를 따로 처리하지 않아도 된다.** 칸마다 따로 판단하므로 두 칸 모두 찼다고 나온다.
- **계산이 가볍다.**

## 4. 이 테스트베드에서의 문제

1. **다른 칸의 차가 잘린 사진에 들어온다.** 웹캠은 통로 A 건너편의 1~14번 줄을 30°로 비스듬히 본다. 통로 A에 선 차, 옆 칸의 차가 칸 영역을 덮으면 빈 칸도 찼다고 나오기 쉽다. 이런 사진을 `empty`로 많이 넣어 가르칠 수는 있지만 완전히 막기는 어렵다.
2. **카메라 자리에 묶인다.** 칸 영역이 화면 좌표라 카메라가 밀리면 다시 정해야 한다. 카메라 각도가 크게 바뀌면 다시 학습해야 할 수도 있다.
3. **데이터를 새로 찍어야 한다.** 지금까지 찍은 사진은 카메라를 손으로 들거나 자리를 바꿔 가며 찍어서 칸 영역이 사진마다 다르다. 카메라를 고정한 뒤에 다시 찍어야 한다.
4. **물체 오탐이 다시 생길 수 있다.** 지우개가 놓인 칸을 `occupied`로 배우지 않도록 3~7차 때처럼 물체 사진을 다시 넣어야 한다.
5. **차 위치는 안 나온다.** 확장 모드(S7)에는 차의 좌표가 필요하므로 탐지 모델(M8)은 그대로 있어야 한다. 모델 두 개를 같이 돌리게 된다.

## 5. 언제 이 방식이 더 나은가

- 카메라가 칸을 **위에서 거의 수직으로** 보아 칸끼리 겹치지 않을 때
- 칸이 화면에 크게 보이고, 탐지 모델이 차를 자주 놓칠 때
- 칸이 많고(수백 칸) 차 위치는 필요 없을 때

PARKIT은 비스듬한 카메라이고 확장 모드에 차 위치도 필요하므로, **기본은 바닥 접점(22 문서)으로 두는 것을 추천한다.**

## 6. 써 볼 만한 곳

- **비교 실험:** 같은 영상으로 두 방식을 돌려 정확도와 지연을 표로 비교하면, 발표에서 "왜 이 방식을 골랐나"의 근거가 된다. 4절 4번의 자동 라벨 덕분에 데이터 준비 부담이 작다.
- **두 번째 의견:** 두 방식의 답이 다르면 상태를 바로 바꾸지 않고 신뢰도(`confidence`)를 낮추거나 몇 초 더 지켜본다.
