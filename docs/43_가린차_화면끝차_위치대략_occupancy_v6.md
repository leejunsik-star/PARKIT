# 43. 웹 지도에서 가린 차·화면 끝 차를 "위치 대략"으로 보이기 → occupancy_v6 (2026-11-08)

## 1. 문제 (11-08 실행 화면, 카메라 1대)

1. **앞차 뒤의 차가 웹 지도에 안 나옴.** 판정 화면에서 뒤차는 `0.87 aisle cut`(앞차 `#3`에 아래가 가린 상자)로 잘 잡혔는데, 웹 지도에는 앞차만 나왔다.
2. **화면 바깥쪽 차가 웹 지도에 안 나옴.** 판정 창 평면도에는 접점이 찍히는데 웹 지도에는 그 차가 없었다.

**원인:** 접점이 가까워 두 차가 한 대로 합쳐진 것이 아니다. 웹 지도로 넘기는 `tracking_bridge.py`가 아래 변이 바닥 접점이 아닌 상자를 버렸다.
- **다른 차에 아래가 가린 상자:** 아래 변이 앞차 지붕 위에서 끝나서, 접점이 **앞차 자리**에 찍힌다. 그대로 쓰면 뒤차가 앞차 위치에 나온다.
- **화면 끝에 닿은 상자:** 아래 변 가운데가 차 가운데가 아니라 보이는 부분의 가운데다.

판정 창 평면도는 모든 상자의 접점을 그대로 찍어서 둘이 달라 보였다.

## 2. 고친 방법

버리던 상자를 **대략 위치**로 웹 지도에 넣고, 점선 아이콘으로 "위치 대략"이라고 표시한다.

### 2.1 앞차에 가린 차

확실히 아는 것은 두 가지다.
1. 뒤차는 카메라에서 뒤차 상자 쪽으로 그은 선(시선) 위에 있다.
2. 앞차가 가렸으니 앞차보다 멀다.

그래서 **시선을 따라가다 앞차의 뒤 끝을 막 지난 곳(✕)**을 뒤차 위치로 쓴다. 실제 뒤차는 ✕이거나 조금 더 뒤다.

```
 (위에서 내려다본 그림)
      카메라 ●
               \      ← 시선
              [ 앞차 ]   ← 예전: 뒤차 접점이 여기 찍혀서 버림
                  \
                   ✕     ← 지금: 뒤차 "대략 위치"
                    \
                   [ 뒤차 ] ← 실제 (✕이거나 조금 더 뒤)
```

- 앞차 뒤 끝은 판정의 P2a와 같이 잡는다. 앞차가 통로 차면 접점에서 3.2cm(`occluder_depth_cm`), 칸에 선 차면 6.5cm(`car_length_cm`)만큼 카메라 반대쪽이다.
- 판정이 잘린 차를 **감시 칸**으로 정했으면(`slot_cut`) 그 칸의 예상 접점을 쓴다. 지도의 "주차 중" 칸과 위치가 맞는다.
- **감시 밖 칸**으로 정해졌으면 시선 점을 쓴다. 그 칸 예상 접점은 합성 시험에서 10~12cm 틀렸다(뒤차가 실제로는 통로에 있었음).

### 2.2 화면 옆 끝에 걸린 차

아래 변의 높이(깊이)는 맞으므로 접점을 그대로 쓴다. 줄 방향으로는 치우칠 수 있다. 화면 **아래** 끝에 잘린 상자는 아래 변이 바닥이 아니므로 예전처럼 버린다.

### 2.3 웹 지도 표시

- 대략 위치인 차는 점선 아이콘과 불확실 원으로 그린다. 범례에 "점선 = 위치 대략"이 있다.
- 차를 고르면 상태에 "다른 차에 가려 위치 대략" 또는 "화면 끝에 걸려 위치 대략"이 붙는다.
- `/api/state` 차량에 `approx`(`"cut"` / `"edge"` / `null`), 상태에 `approx_contacts`(대략 위치로 보낸 점 수)가 있다.

### 2.4 카메라 2대일 때

- 다른 카메라가 같은 차를 정확히 보고 있으면, 대략 위치로 그 차를 옮기지 않는다. 그 카메라도 이 차를 본다는 것만 남긴다.
- 정확한 점 가까이(5cm 안)의 대략 위치는 새 차로 만들지 않는다.
- 대략 위치와 정확한 점을 같은 차로 이을 때는 `approx_radius_cm`(5cm)만큼 여유를 더 준다. 대략 위치가 없으면 추적 규칙은 예전과 같다.
- 처음에는 이 규칙 없이 넣었다. 그러자 남·북 두 카메라가 보는 통로 차 하나가 한쪽 화면 끝에 걸린 동안 두 대로 갈라졌고(test_aisle_contact_shift 14/16), 이 규칙을 넣어 고쳤다.

칸 판정(빈 칸 / 주차됨)은 바뀌지 않는다. 판정 코드는 `approx_mat`, `edge_bottom` 값만 더 남긴다.

## 5. 남은 것

- **실제 웹캠으로 확인하지 않았다.** 11-08 화면과 같은 배치에서 뒤차가 점선으로 앞차 뒤에 나오는지, 화면 끝 차가 나오는지 본다.
- **대략 위치는 2~4cm 어긋난다.**
  - 뒤차는 실제보다 앞차 쪽으로 붙어 보인다(실제는 더 뒤일 수 있음).
  - 화면 끝 차는 줄 방향으로 치우친다.
- 판정이 잘린 차의 칸을 틀리게 고르면(39 문서 4절의 원래 있던 문제) 지도 위치도 그 칸으로 10cm 넘게 틀린다.
- 앞차와 뒤차가 아주 붙어 있으면 추적기가 같은 차로 이을지 애매하다고 보고, 잠깐 "ID 연결 불확실"로 나올 수 있다.
- 웹을 고치면 `web`에서 `npm ci`, `npm run build`를 다시 해야 한다.
