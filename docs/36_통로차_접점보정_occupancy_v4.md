# 36. 통로 차 접점 반 폭 보정 → occupancy_v4 (2026-11-04)

웹 지도(차량 추적)에서 반대쪽 카메라 두 대가 같은 통로 차를 두 대로 보이게 하던 문제를 고쳤다.
`docs\도구\occupancy_v3`를 `occupancy_v4`로 복사해서 고쳤다. v3는 그대로 두었다.

## 1. 문제

- 칸 판정은 문제가 없다. 카메라마다 자기 예상 접점(P2b)으로 칸을 정하고, 칸별 결과만 합친다(P9). 그래서 반대쪽 카메라의 접점이 달라도 같은 칸으로 판정한다.
- 웹 지도의 통로 차는 실시간 좌표라 차이가 그대로 드러난다.
  - 상자 아래 끝(접점)은 각 카메라에 가까운 옆면이다. 그래서 통로를 따라 달리는 차는 두 카메라 점이 **차 폭(3.2cm)** 만큼 떨어진다.
  - 추적기는 다른 카메라 점을 `cross_camera_radius_cm`(2cm) 안에서만 같은 차로 잇는다. 그래서 한 차가 **두 대로** 나왔다.

## 2. 고친 것

| 파일 | 내용 |
|---|---|
| `tracking_bridge.py` | `shifted_contact()` 추가. 추적기에 넣기 전에 **통로 차(kind `aisle`) 접점만** 카메라에서 먼 쪽(`CamGeom.far_dir`, 카메라 자세로 계산)으로 `aisle_contact_shift_cm`만큼 민다. `submit()`에 `geom`(카메라) 인자 추가. geom이 없으면 이전과 같다(동료 데모·시험 호환). 보낸 상태의 `tracking_config`에 보정값을 같이 적는다 |
| `occupancy.py` | 두 줄만 고침: 추적 연결을 만들 때 기본 보정값 = 판정 숫자 `car_width_cm` ÷ 2, `submit()`에 카메라 `c.geom` 넘김 |
| `tracking_config.example.json` | `aisle_contact_shift_cm: 1.6` 추가 |
| `test_aisle_contact_shift.py` | 새 시험 16개 |
| `README.md`, `TRACKING.md`, `make_handoff.py` | v4 설명과 이름(`handoff_점유판정v4_<날짜>`) |

**설정**: 숫자는 코드에 고정하지 않았다. 기본값은 `car_width_cm`의 반이다. `run.json`에 `"vehicle_tracking": {"aisle_contact_shift_cm": 1.6}`을 적거나 `--tracking-config` 파일로 바꾼다. **0이면 보정하지 않는다**(v3와 같음).

**hun 지시로 하지 않은 것**
- 칸에 선 차를 추적기·웹에서 빼는 것(계획 ①): 하지 않았다. **칸에 선 차(`slot`, `unmonitored`)의 접점도 지금처럼 웹 지도에 보낸다.** 보정도 하지 않고 접점 그대로 쓴다.
- 통로 차를 숨기거나 지우는 규칙(계획 ②의 "근처 칸이 차 있음이 되면 바로 지우기", ③의 "칸이 차 있음이면 통로 좌표 안 보내기"): 넣지 않았다.

**바꾸지 않은 것**
- 칸 판정 코드(parkit_judge, parkit_state)와 판정 창 그림: 판정 창의 접점 점은 보정 전 자리에 그대로 그린다.
- 웹 화면(web\src, web\dist): 바꾸지 않았다.
- `slot_cut`, `uncertain`, 화면 가장자리 상자, 아래가 잘린 상자: 이전처럼 좌표 갱신에 쓰지 않는다.

## 4. 웹 지도 "내 차만 보기" (같은 날 추가)

내 차를 고른 뒤 다른 차를 지도에서 숨길 수 있게 했다. 웹 화면만 바꿨고 추적기·판정은 그대로다.

| 파일 | 내용 |
|---|---|
| `web\src\tracking.js` | `visibleVehicles(차 목록, 고른 ID, 켬/끔)` 추가. 켜면 고른 차만 돌려준다. 고른 차가 목록에 없으면(추적 끝, ID 바뀜) **모든 차를 돌려주고** `mineMissing`을 알린다. 다른 차를 숨긴 채로 남으면 다시 고를 수 없기 때문이다 |
| `web\src\main.jsx` | MY VEHICLE 칸에 **[내 차만 보기] / [다른 차량도 보기]** 버튼. 켜면 지도 제목이 "내 차량만", 범례에 "다른 차량 숨김"이 나온다. 내 차를 놓치면 "내 차량을 찾을 수 없어 모든 차량을 표시합니다. 내 차량을 다시 선택하세요." 안내가 나온다. [선택 해제]를 누르면 옵션도 꺼진다. 칸 색(빈자리·주차 중)은 계속 보인다 |
| `web\src\tracking.test.js` | 시험 1개 추가 |
| `web\dist` | 다시 빌드(`index-CLBznvE-.js`) |

- **Node 설치**: 이 PC에 conda 새 환경 `parkit-node`(conda-forge nodejs 24.22.1)를 만들었다. base와 aienv는 건드리지 않았다. 빌드하는 법(Git Bash):
  `export PATH="/c/miniconda3/envs/parkit-node:$PATH"` → `docs\도구\occupancy_v4\web`에서 `npm ci`, `npm test`, `npm run build`
- **시험**: 웹 시험 7 / 7 통과(새 시험 포함). `python tracking_demo.py --port 8766`(합성 데모)을 띄워 브라우저로 확인:
  - 차 선택 → [내 차만 보기]: 지도에 고른 차 1대만 남음, 제목 "내 차량만"
  - [다른 차량도 보기]: 다시 모든 차
  - 고른 차가 사라짐: 안내가 나오고 모든 차가 다시 보임
  - [선택 해제]: 옵션 꺼짐
  - 브라우저 오류 없음

## 5. 남은 것

- **실제 웹캠 2대로 확인**: 매트 양쪽에 두고 보정한 뒤 통로에 차를 세워, 웹 지도에 한 대로 나오는지 본다. 위 숫자는 합성 카메라 계산이다.
- 칸에 드나들며 도는 순간(차가 세로로 놓임)은 보정해도 3cm 넘게 남는다. 그래서 잠깐 두 대로 보일 수 있다.
- 칸에 선 차는 보정하지 않았다. 반대쪽 카메라 두 대가 같은 칸의 차를 보면 접점이 차 길이(6.5cm)만큼 달라서, 웹 지도에 두 대로 나올 수 있다(v3와 같음). 고치려면 칸 차는 예상 접점(P2b)으로 차 가운데를 되돌려 쓰는 방법이 있다(다음에 정함).
- 통로 ↔ 칸으로 넘어가는 순간의 시간 차이(계획 ②)와 분석 간격(통로 추적에는 5~10프레임 권장, 지금 15)은 그대로다. 시연에서는 `--preset demo`나 `analyze_every_frames`로 맞출 수 있다.
