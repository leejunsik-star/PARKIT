# 38. 잘린 차 판정 구간과 칸에 선 차의 가림 수정 → occupancy_v5 (2026-11-07)

통로 차에 아래가 잘린 차가 제 칸에 있는데도 `?33,34`처럼 두 칸으로 나오던 문제를 고쳤다(1~3절).
낮은 카메라에서 앞차 뒤에 덮인 칸이 "차 없음"으로 나오던 문제도 같은 폴더에서 고쳤다(4절).
`docs\도구\occupancy_v4`를 `occupancy_v5`로 복사해서 고쳤다. v4는 그대로 두었다. 복사할 때 `logs`와 `__pycache__`는 뺐고, 11-07에 다시 보정한 v4 설정은 그대로 가져왔다.

## 1. 문제

실행 화면에서 33번 차는 `#33 cut`, 34번 차는 `?33,34 cut`으로 나왔다. 두 차 모두 제 칸에 있었다.

- 잘린 상자는 아래 변이 실제 바닥이 아니다. 그래서 "차가 있을 만한 구간"을 긋고, 그 구간이 지나는 칸을 후보로 삼는다(P2a).
- v4는 이 구간을 **통로 차 가운데**의 뒤 끝에서 시작했다. 나란한 두 차의 구간이 한 점에서 출발한다.
- 사진에서 시작점은 x 33.05로, 33번과 34번의 경계(x 약 33.44)보다 33번 쪽이었다. 그래서 34번 차의 구간만 33번을 약 0.4cm 스치고 두 칸으로 세어졌다.
- 통로 차를 34번 쪽으로 옮기면 결과가 뒤집혀 33번 차가 `?34,33`이 된다. 11-07 실행 기록에도 `[33, 34]`와 `[34, 33]`이 둘 다 남아 있다.

## 2. 고친 것

| 파일 | 내용 |
|---|---|
| `parkit_judge.py` | `_sight_start()` 추가. 가리는 차가 **통로 차일 때만** 구간을 잘린 차 자기 시선(카메라 바닥점 → 잘린 접점) 위에서, 기존 뒤 끝과 깊이가 같은 곳부터 시작한다. 카메라 자세가 없으면 기존 뒤 끝을 쓴다 |
| `test_geometry.py` | 시험 1개 추가: 통로 차가 나란한 두 차를 같이 가릴 때 좌우 ±1cm에서 각자 제 칸 |
| `28_점유판정_프로그램_사용법.md`(v5 복사본) | 6절 P2a 설명, 7.1절 시험 결과 |
| `README.md`, `TRACKING.md`, `make_handoff.py` | v5 설명과 이름(`handoff_점유판정v5_<날짜>`) |

이 수정에는 새 설정 숫자가 없다. `occluder_depth_cm`, `car_length_cm`를 그대로 쓴다.

**주차된 차가 가릴 때는 고치지 않았다.** 처음에는 함께 고쳤는데, 대각선 카메라에서 나빠졌다(빈 칸을 차 있음으로 본 횟수 4 → 110). 옆 칸 차가 같은 줄의 차를 가리면, 차 길이만큼 간 깊이가 진짜 접점을 지나쳐 제 칸을 놓친다.

- **사진 상황 재현**: 화면의 상자 좌표를 넣으면 v4는 `33`, `?33,34`, v5는 `33`, `34`다. 통로 차를 x 32.22~34.62에서 옮겨도 v5는 두 차 모두 제 칸이다. 상자 좌표는 작은 사진에서 눈으로 읽은 값이다.

**합성 카메라 비교**: 나란한 두 칸의 차 앞에 통로 차를 두었다. 통로 차를 좌우(±2cm, 0.5cm 간격), 칸과의 간격(0.3, 1.0cm), 높이(2, 3, 4cm)로 바꿔 잘린 상자 7,776개를 봤다. 임시 스크립트로 돌렸고 저장소에는 넣지 않았다.

| 카메라 | 제 칸으로 판정 (v4 → v5) | 다른 칸으로 판정 (v4 → v5) | 빈 칸을 차 있음으로 (v4 → v5) |
|---|---|---|---|
| 정면 CAM-1 (51, -8) | 52.6% → **87.0%** | 66 → 0 | 0 → 0 |
| 정면 CAM-2 (23, -8) | 47.3% → **85.2%** | 66 → 0 | 0 → 0 |
| 남쪽 정면 (34.8, 80) | 38.2% → **69.4%** | 100 → 0 | 0 → 0 |

| 대각선 (86, -8) | 8.7% → 8.7% | 10 → 2 | 4 → 2 |
| 남쪽 대각선 (-6, 63) | 0% → 0% | 42 → 12 | 24 → 12 |

- 나머지 대부분은 `?`(제 칸 포함)이다. 이 경우 칸은 "차 있음"이 아니라 "가려짐"으로 잡힌다.
- 나빠진 경우도 있다. v4에서 제 칸이던 상자 중 54개가 v5에서 `?`로 바뀌었다(정면 CAM-1 14, CAM-2 2, 남쪽 정면 2와 36). 제 칸을 포함한 `?`이고 다른 칸으로 잘못 정한 것은 아니다.
- 대각선은 거의 그대로다. 시선이 비스듬해 구간이 실제로 여러 칸을 지나므로 대부분 `?`로 남는다(약 90%).

## 4. 칸에 선 차의 가림 (P5)

**문제**: 줄 끝에서 줄을 따라 보는 낮은 카메라(11-07 보정: 렌즈 바닥 (-27.6, 22.8), 높이 8.9cm)에서 앞차 뒤의 차가 탐지되지 않았다. 그런데 P5는 통로 차만 가리는 차로 쳐서, 덮인 칸이 "가려짐"이 아니라 "차 없음"이 되고 시간이 지나면 EMPTY로 나왔다.

**고친 것**

| 파일 | 내용 |
|---|---|
| `parkit_judge.py` | P5에 칸에 선 차(`slot`, `slot_cut`, `unmonitored`)를 넣었다. 그 칸보다 카메라에 가까운 차(상자 아래 변이 칸 영역 아래 끝보다 화면에서 아래)만 쓴다. 판정 이유에 `(parked)`가 붙는다 |
| `parkit_config.py` | `occlusion_ratio_parked` 추가, 기본 0.9 |
| `config\run.json` | `occlusion_ratio_parked: 0.6` (지금의 낮은 카메라용). `run_2대.json`, `run_v2.json`은 기본값 0.9를 쓴다 |
| `test_geometry.py` | 시험 3개 추가(5-1번) |

- `uncertain` 상자는 넣지 않았다. 통로 차 판정(`occlusion_ratio` 30%)은 그대로다.

**기준을 따로 둔 까닭**: 칸에 선 차는 떠나지 않아서, 잘못 가려짐이 되면 차가 떠날 때까지 그 칸의 빈자리를 알 수 없다. 차 한 대만 두고 잘 보이는 빈 칸이 가려짐이 되는 비율을 쟀다.

| 카메라 (합성, 마지막 줄만 실제 보정값) | 0.3 | 0.6 | 0.75 | 0.9 |
|---|---|---|---|---|
| 정면 CAM-1, CAM-2, 남쪽 정면 (15cm) | 0% | 0% | 0% | 0% |
| 15~27쪽 낮게 (6cm) | 3.6% | 0% | 0% | 0% |
| 대각선, 남쪽 대각선 (15cm) | 2.3~2.4% | 0.7% | 0% | 0% |
| 지금 보정 (줄 끝 8.9cm) | 5.2% | 2.6% | 0.8% | 0% |

- 이 비율은 칸 전체에 대한 값이다. 차 바로 옆 칸만 보면 훨씬 높다. 대각선에서 차 한 대는 옆 칸을 최대 86% 덮는다. 그래서 기본값을 0.9로 두었다.
- 지금 카메라의 2.6%는 대부분 앞차가 실제로 덮은 칸이다.

**사진 재현 (지금 보정, 기준 0.6)**: 상자 좌표는 사진에서 눈으로 읽었다.

| 칸 | 덮임 | v5 수정 전 | 수정 후 |
|---|---|---|---|
| 13, 12, 11 | 100%, 84%, 62% | 차 없음 | **가려짐** |
| 10, 9 | 38%, 14% | 차 없음 | 차 없음 |
| 29, 30 | 97%, 75% | 차 없음 | **가려짐** |
| 31, 32 | 49%, 26% | 차 없음 | 차 없음 |

**시험**: test_geometry 45 / 45, test_pipeline 33 / 33, test_aisle_contact_shift 16 / 16, test_vehicle_tracker 17개, test_tracking_integration 5개, test_tracking_replay 통과. test_autoref 12 / 13(원래 있던 대각선 실패).

**한계**
- 찾지 못한 차를 찾아 주는 수정이 아니다. 덮인 칸은 "차 있음"이 아니라 "가려짐"이 된다.
- 기준 아래로 덮인 칸(사진의 10, 31번)은 차가 있어도 탐지되지 않으면 여전히 "차 없음"이다.
- **원래 있던 문제**: 뒤차가 잘린 상자로 잡혀도 칸 번호가 어긋날 수 있다. 합성 시험에서 11번 차가 `?10,9,8`이나 `slot_cut 10`으로 나왔다. `slot_cut 10`이면 빈 10번이 "차 있음"이 된다. v4도 같고 이번에 고치지 않았다. 앞서 넣은 시선 수정은 주차된 차가 가릴 때 쓰지 않기 때문이다(2절).

## 5. 남은 것

- **실제 웹캠으로 확인**: 위 결과는 합성 카메라와 사진 재현이다. 같은 자리에 차를 두고 `occupancy_v5`를 돌려, 통로 차가 지나갈 때 33·34번이 제 칸으로 나오는지 본다. 낮은 카메라에서는 앞차 뒤의 칸이 노랑(가려짐)이 되는지 본다.
- **잘린 뒤차의 칸 번호**: 4절의 원래 있던 문제.
- **정면에서도 `?`가 남는다**: 화면 가장자리 쪽 칸은 시선이 비스듬해 13~32%가 `?`다.
- **대각선 카메라의 잘린 차**: 위와 같은 이유로 이번 수정으로는 거의 나아지지 않는다.
- **git에 올릴 때**: `.gitignore`의 `dist/` 때문에 `occupancy_v5\web\dist`가 빠진다. v4처럼 Node 없는 컴퓨터에서 웹 지도를 쓰려면 `git add -f`로 넣거나 제외 규칙을 더해야 한다.
- `docs\26`(판정 규칙 설명)과 저장소의 `docs\28` 원본은 고치지 않았다.
