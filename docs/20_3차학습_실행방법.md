# 3차 학습 실행 방법 (2026-10-31)

2차 학습(17·18 문서)과 같은 방식으로, 새로 찍은 5·6·7차를 더해 M6~M8을 학습하고 M5와 비교한다.
나누기와 채점은 PC(CPU)에서 하고, 학습은 코랩(T4)에서 한다. 2차용 파일(split_2차, handoff_2차, make_split_2차.py, colab_train_2차.ipynb, eval_2차.py)은 고치지 않았다.

## 0. 만든 파일

## 1. 나누기 (이미 했음)

배치째로 나눴다. 1~4차·3차·COCO는 split_2차와 똑같다(스크립트가 split_2차 폴더와 파일 이름을 비교해서 확인한다).

| 출처 | train | val | test (시험 세트) |
|---|---|---|---|
| 1차 집 | A_1~A_5, B_1~B_4 (27장) | A_6, B_5 (6장) | A_7, B_6 (6장) → T1 |
| 2차 학교 | s1~s6 (36장) | s7 (6장) | s8, s9 (12장) → T2 |
| 4차 차 적음 | little_car_1, _3 (14장) | little_car_2 (5장) | little_car_4 (7장) → T3 |
| 3차 빈 매트 | x_0001~0021 (21장) | x_0022~0024 (3장) | x_0025~0030 (6장) → T4 |
| COCO | seed 1 (60장) | 없음 | seed 2 (30장) → T5 |
| 6차 차+물체 | mix_1~3, mix_6~8 (34장, 213상자) | mix_5 (5장) | mix_4, mix_9 (12장, 63상자) → T6 |
| 7차 물체만 | obj_1~4 (23장) | obj_5 (6장) | obj_6 (6장) → T7 |
| 5차 다른 배경 | bg_1~4 (17장, 71상자) | bg_5 (4장) | bg_6 (4장, 27상자) → T8 |
| 합계 | 232장 | 35장 | 83장 |

T6의 mix_9는 어두운 조명이다. val은 2차의 20장에 mix_5·obj_5·bg_5를 더한 35장이다.

모델별 train (val 35장, test는 모두 같다):

| 모델 | train 구성 | 장 수 | 차 없는 사진 |
|---|---|---|---|
| M5 | 1·2·4차 + 3차 21장 + COCO 60장 (2차에서 학습, 다시 학습하지 않음) | 158 | 81 (51%) |
| M6 | M5 + 6차 | 192 | 81 (42%) |
| M7 | M6 + 7차 | 215 | 104 (48%) |
| M8 | M7 + 5차 (= train 전부) | 232 | 104 (45%) |

`train_M5.txt`는 split_2차의 M5와 같은지 확인하려고 만든 것이다. M5용 yaml은 만들지 않았다.

다시 만들려면 아래를 실행한다. `split_3차`와 `split_3차.zip`만 지우고 다시 만들며, 원본과 split_2차는 건드리지 않는다.

cd docs\도구

확인만 하려면 `python make_split_3차.py --check`를 실행한다. 결과는 `split_3차\확인결과.txt`에 남는다.

## 2. 코랩에서 학습

1. `dataset\split_3차.zip`을 구글 드라이브 **내 드라이브** 맨 위에 올린다.
2. `docs\도구\colab_train_3차.ipynb`를 코랩에서 연다(드라이브에 올려 **Google Colaboratory로 열기**, 또는 colab.research.google.com → 파일 → 노트 업로드).
3. **런타임 → 런타임 유형 변경 → T4 GPU** → 저장.
4. **런타임 → 모두 실행**.

- 설정은 2차와 같다: `yolo26n.pt`에서 처음부터, `imgsz=640, epochs=100, batch=16, hsv_h=0.05, seed=0, deterministic=True`.
- 모델 하나가 끝날 때마다 드라이브 `parkit_runs_3차\M6` ~ `M8`에 `best.pt`, `results.png`, `results.csv`, `args.yaml`을 저장한다.
- **연결이 끊기면** 노트북을 처음부터 다시 실행한다. 드라이브에 `best.pt`가 있는 모델은 건너뛰고, 중간에 끊긴 모델만 처음부터 다시 학습한다.
- 한 모델만 다시 하려면 드라이브의 그 모델 폴더를 지운다. 일부만 돌리려면 2번 셀의 `MODELS`를 고친다.
- 예상 시간(추정): 모델 하나에 25~30분, 세 개 합쳐 1시간 반 안팎.

## 3. PC에서 채점

1. 드라이브의 `parkit_runs_3차`를 내려받는다. `M6\best.pt` ~ `M8\best.pt`의 이름을 `M6.pt` ~ `M8.pt`로 바꿔 `docs\도구\models`에 둔다.
2. 아래를 실행한다. 인자가 없으면 `best.pt`와 `models\M5~M8.pt` 중 있는 것을 모두 채점한다.

```
cd docs\도구
python eval_3차.py
```

- 고른 모델만 채점: `python eval_3차.py best.pt models\M5.pt models\M8.pt`
- 신뢰도 기준 바꾸기: `--conf 0.4` (기본 0.25)
- 결과는 `docs\도구\eval_3차_결과\eval_3차.csv`, `eval_3차.md`에 저장된다. 마크다운 표는 한 표에 넣으려고 칸을 합쳤고, 값을 따로 보려면 csv를 본다.
- CPU에서 모델 하나에 10초 안팎 걸린다.

숫자 보는 법:
- **차 있음 (T1, T2, T3, T6, T8)**
  - P, R, mAP50은 `model.val(split=test)` 값이다.
  - 놓친 차와 잘못 잡은 상자는 신뢰도 0.25 이상 상자로 센다. 상자를 신뢰도가 높은 것부터, 아직 짝이 없는 정답 중 IoU가 가장 큰 것과 짝짓는다. IoU가 0.5 이상이면 맞은 상자다. 짝이 없는 정답은 "놓친 차", 짝이 없는 상자는 "잘못 잡은 상자"다.
- **차 없음 (T4, T5, T7)**: 신뢰도 0.25 이상 상자는 모두 오탐이다. "오탐 사진"은 상자가 하나라도 나온 사진 비율이다.

지금 보이는 것(M5 기준):
- 매트 위 물체는 여전히 차로 잡는다. T7은 6장 모두에서 상자가 15개 나왔고, T6에서도 잘못 잡은 상자가 18개다. 3차 학습으로 줄이려는 숫자가 이것이다.
- 다른 배경(T8)은 best와 M5 모두 이미 거의 완벽하다. 4장, 27대뿐이라 차이를 보기 어렵다.

주의:
- **T6·T8 라벨을 18 문서 8절 계획대로 M5 자동 라벨에서 고쳤다면**, 사람이 못 고친 M5의 실수가 정답으로 남아 M5에 유리할 수 있다(15 문서 2절과 같은 문제). T7은 빈 라벨이라 이 문제가 없다.
- 시험 사진이 적다. 특히 T7과 T4는 6장, T8은 4장이다. 상자 몇 개 차이는 우연일 수 있다(18 문서 5절).
- M7·M8은 train의 절반 가까이가 차 없는 사진이다. 차를 놓치는 쪽으로 기우는지 T2·T6의 놓친 차 수로 같이 본다.
- 숫자가 좋아도 실제 웹캠에서 처음 보는 물체로 한 번 더 확인한다(18 문서 7절처럼 `live_detect_winmac.py`로 비교).
