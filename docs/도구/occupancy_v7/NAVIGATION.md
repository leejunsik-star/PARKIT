# 빈자리 내비게이션과 지도 탐색

## 실행

PARKIT 루트에서 Mac:

```sh
.venv-gui/bin/python docs/도구/occupancy_v7/occupancy.py --web
```

Windows는 활성화한 가상환경의 `python`으로 실행한다. 기존 서버가 실행 중이면 종료 후 다시 실행한다. 브라우저에서 http://127.0.0.1:8765/ 를 열고 새로고침한다. Larix 사용 시 수신기와 휴대폰 송출도 유지한다.

카메라 없이 확인할 때:

```sh
.venv-gui/bin/python docs/도구/occupancy_v7/tracking_demo.py
```

합성 데모는 실제 카메라나 탐지 성능을 검증하지 않는다.

## 사용

1. 지도에서 내 차량을 클릭한다.
2. 초록색 EMPTY 주차칸을 클릭하면 목적지로 선택되고 안내가 시작된다.
3. 경로, 목적지 진입점, 남은 거리(cm)를 확인한다.
4. 차량 선택 후에도 지도는 자동으로 움직이지 않는다. 드래그·휠·핀치로 자유롭게 탐색하며 목적지는 유지된다. 따라가기 모드는 제거했다.
5. `전체 보기`는 지도 범위를 복원하고 `안내 취소`는 목적지를 해제한다.

마우스 드래그/한 손가락 이동, 휠/두 손가락 확대·축소, +/− 버튼을 지원한다. 6픽셀 이상의 드래그는 주차칸 클릭으로 처리하지 않는다. 키보드 Tab과 Enter/Space로 차량·칸을 선택할 수 있다.

## 추적 누락

- 0.5초 이내에는 전달된 속도를 이용해 제한적으로 예측 표시한다. 실측과 구분해 `위치 추정 중`으로 표시하며 예측만으로 도착을 확정하지 않는다.
- 0.5초 초과, ID 연결 불확실, 위치 대략, 웹 연결/분석 중단: 마지막 확인 위치와 회색 경로를 표시하고 안내를 멈춘다.
- 3초 초과 또는 차량 제거: 재선택 안내. 동일 ID가 신뢰 가능한 관측으로 복구되면 재개한다.
- 새로운 ID는 후보가 하나여도 자동 선택하지 않는다. 사용자가 확인해야 한다. 목적지는 유지한다.
- 서버 세션이 바뀌면 같은 ID 문자열이어도 다른 차량일 수 있으므로 재선택한다.
- 목적지 상태가 EMPTY가 아니면 안내를 중지한다. 가림을 빈자리로 간주하지 않는다. 주차칸 예약 기능은 없다.

시간 값은 내비 설정이며 기존 Tracker의 LOST/REMOVED 설정을 바꾸지 않았다. 현재 수신 시각 기반이므로 실제 분석 주기·네트워크 지연에 맞춰 조정해야 한다.

## 통로 설정 (반드시 실제 매트와 대조)

`config/navigation_layout.json`에 매트 cm 좌표로 정의한다. x는 오른쪽, y는 아래 방향이다.

기본값은 현재 칸표 78.3×55.4cm에 대해 가정한 다음 통로다:

- 위 가로 통로: (3, 14.6) → (72, 14.6)
- 왼쪽 세로 연결: (3, 14.6) → (3, 41.85)
- 아래 가로 통로: (3, 41.85) → (72, 41.85)
- 오른쪽 세로 연결: (72, 14.6) ↔ (72, 41.85)

`nodes`는 점 이름과 [x,y], `edges`는 연결할 두 점 이름이다. 기본 양방향이며 `["점A", "점B", "oneway"]`로 쓰면 A→B만 가능하다. 주차칸 진입점은 기존 SlotTable의 inner 중앙 x와 entrance_y를 재사용한다.

설정 변경 후 서버를 다시 시작한다. 큰 주차장/다른 도면에서는 mat 크기와 nodes/edges도 해당 배치에 맞춰 수정해야 한다. 칸표 크기와 불일치하거나 통로가 칸을 가로지르면 내비만 비활성화하고 기존 점유/웹지도는 유지한다.

`max_snap_cm`(기본 6): 차량·주차칸 진입점을 통로로 연결할 최대 거리. 너무 멀거나 연결선이 다른 주차칸을 가로지르면 경로를 거절한다. 주차칸 안의 차량은 자기 칸 진입점으로 나오는 구간만 허용한다.

`arrival_cm`(기본 1.5): 주차칸 진입점 도착 거리. 주차 완료 판정이나 자동 조향이 아니다.

최단 경로는 다익스트라로 계산한다. 지도에 없는 벽·기둥·다른 차량·차체 크기·회전 반경은 자동으로 회피하지 않는다. 통로 배치와 충분한 여유 공간을 실제 환경에서 확인해야 한다. 이번 구현은 시연용 경로 안내이며 출구/입구 추천, 음성 안내, 통로 편집 GUI는 포함하지 않는다.

## 파일과 데이터 흐름

- `navigation.py`: 통로 설정 검증, 시작점/목적지 연결, 최단 경로.
- `parking_api.py`: GET `/api/navigation`, GET `/api/route?vehicle_id=...&destination=...&session_id=...`. 서버의 실제 현재 위치·점유·세션을 검증한다.
- `tracking_bridge.py`: 기존 칸표 레이아웃에 entrance_y 제공.
- `vehicle_tracker.py`: 기존 속도를 읽기 전용 snapshot에 추가. 매칭 알고리즘 변경 없음.
- `web/src/navigation.js`, `useNavigation.js`: 사용자별 목적지, 안내 상태, 요청 취소/이전 응답 무효화. 선택은 브라우저 탭별이며 다른 사용자 선택을 덮어쓰지 않는다.
- `web/src/MapViewport.jsx`: 드래그/휠/핀치/viewBox. 실측 좌표는 그대로 둔다.
- `web/src/main.jsx`, `style.css`: 빈자리 선택·경로·안내 상태 화면.
- `test_navigation.py`, `web/src/navigation.test.js`: 새 회귀 검사.

탐지 → 기존 점유/추적 → StateStore → WebSocket → 웹지도. 경로 요청은 FastAPI에서 StateStore 복사본을 읽어 처리하며 카메라 분석 스레드를 호출하지 않는다.

## 검증

v7 폴더에서:

```sh
python -m unittest test_navigation test_camera_input test_multi_camera test_vehicle_tracker test_tracking_integration test_tracking_replay test_mycar_links -q
cd web
npm ci
npm run build
npm test
```

Python 44개, 웹 13개 통과(따라가기 테스트 제거). 점유 상태 재생 off/on/20배속 107행 동일. Chrome 합성 서버에서 차량/빈자리 선택, API 경로, 휠 줌, 드래그, 전체 보기, 누락/새 ID 수동 확인/목적지 점유/서버 재시작, 모바일 터치 핀치 및 연결 복구를 검증했다. 실제 CCTV를 이용한 새 내비 시연은 아직 검증하지 않았다.

`web/dist`에 빌드 결과를 포함하도록 제외 규칙을 조정했다. 코드 수정 후에는 다시 빌드해야 한다.
