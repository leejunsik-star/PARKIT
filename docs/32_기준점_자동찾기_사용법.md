# 32. 보정 도구 ver2: 기준점 자동 찾기 사용법 (2026-11-04)

손으로 기준점을 4개쯤 찍으면 나머지 기준점을 프로그램이 바닥의 칠한 선에서 찾아 더한다. 원본 보정 도구(calibrate.py)와 판정 프로그램(occupancy.py)은 그대로 두고 새 파일로만 만들었다(31 문서).

## 1. 무엇이 다른가

| | v1 (calibrate.py) | v2 (calibrate_v2.py) |
|---|---|---|
| 기준점 | 손으로 하나씩 (지금 CAM-1은 6~12개) | 손 4개 + 자동 수십~백여 개 |
| 저장 | config\cam_CAM-1.json | config\v2\cam_CAM-1.json |
| 실행 설정 | config\run.json | config\run_v2.json |
| 판정 프로그램 | occupancy.py | 같은 occupancy.py (`--run config\run_v2.json`) |

v2 결과 파일은 v1과 같은 형식에 `auto_ref` 키만 더했다. 그래서 같은 판정 코드로 v1 보정과 v2 보정을 비교할 수 있다.

### 1.1 파일 (모두 docs\도구\occupancy)

| 파일 | 하는 일 |
|---|---|
| calibrate_v2.py | 보정 도구 ver2 화면. calibrate.py를 불러와 넓힌다(원본은 고치지 않음) |
| parkit_autoref.py | 선 예상, 선 찾기, 직선 맞추기, 교점, 손 점 검사 (화면 코드 없음, 매트 치수 없음) |
| make_ref_lines.py | 칸 표 → 이 매트의 기준선 목록. 이 매트 전용 숫자(U자 다리 폭 등)는 여기에만 있다 |
| data\기준선_매트.json | 이 매트의 기준선 158개(입구 tip_row 10, 칸 옆·카스토퍼 edge 148), 기준점 184개 |
| config\run_v2.json | run.json + 기준선 목록 경로(`ref_lines`) + 자동 찾기 설정(`autoref`). 카메라 설정은 `v2/cam_CAM-1.json` |
| config\v2\ | ver2 보정 결과(cam_<이름>.json, 확인 사진) |
| test_autoref.py | 합성 시험 (6절) |
| parkit_synth_mat.py | 시험용 합성 매트(U자 선, 카스토퍼, 기둥, 글자, 화살표)와 일반 주차장 그림 |

## 2. 원리 (짧게)

1. 손 점 4개 이상 → 호모그래피(화면 ↔ 매트)를 대략 구한다.
2. 기준선 목록의 선마다 화면 어디에 있을지 예상한다.
3. 예상선을 따라 일정 간격으로 직각 단면을 뽑고, 단면에서 선의 가장자리(또는 가운데, 끝)를 찾는다.
4. 찾은 점들을 RANSAC으로 직선에 맞춘다. 점이 적거나 흩어지면 "애매함" 또는 "못 찾음".
5. 두 기준선의 교점 = 자동 기준점. 자동 점들로 호모그래피를 다시 구한다(화면 픽셀 기준 RANSAC으로 엉뚱한 점을 뺀다).
6. 찾는 폭을 2 → 1 → 0.5cm로 줄이며 3번 되풀이한다.
7. 손 점을 자동 결과와 비교한다. 1cm 넘게 어긋난 손 점은 경고하고 계산에서 뺀다. 손 점 절반 넘게가 어긋나면 자동 결과를 믿지 않는다.

기준점을 "그려진 모서리"가 아니라 "두 선의 교점"으로 정한 이유: 이 매트는 U자 끝이 둥글고 카스토퍼가 선과 떨어져 있어 기준점 자리에 모서리가 없다. 곧은 선은 어느 주차장에나 있다.

## 3. 보정 순서

docs\도구\occupancy 에서:

```bash
python calibrate_v2.py
```

```bash
python calibrate_v2.py --cam CAM-1 --image 빈매트.jpg
```

0. **카메라 고르기**: `python calibrate_v2.py`만 실행하면 원본과 같은 시작 창이 열린다(웹캠 미리보기, 카메라마다 웹캠 번호). 보정 파일은 config2 를 먼저 보고, 없으면 원본 보정 파일의 웹캠 번호를 쓴다. 보정 창 [입력] 칸에서도 카메라를 바꿀 수 있다.
1. **화면 준비**: 빈 매트가 좋다(차가 있어도 되지만 가린 선은 못 찾는다). 웹캠이면 Space로 멈춰도 되고, Enter를 누르면 저절로 멈춘다.
2. **손 점 4개**: v1과 같이 ① 단계에서 평면도로 칸을 고르고 점 종류(IE-/IE+/IB-/IB+)를 골라 찍는다.
   - 화면 네 귀퉁이 쪽으로 넓게, 앞줄과 뒷줄, 입구 끝과 안쪽 끝을 섞는다. 셋이 한 줄에 서면 안 된다.
   - v1 보정 파일이 있으면 [v1 기준점 가져오기]로 그 점을 가져와도 된다.
3. **Enter (자동 찾기)**: 4초쯤 걸린다. 결과가 색으로 나온다(4절).
4. **확인**
   - 노랑(애매함) 선과 그 교점, 빨간 겹원 손 점을 본다.
   - 틀린 자동 점: 클릭하고 Delete(또는 오른쪽 클릭)로 뺀다. 다시 누르면 되살린다.
   - 조금 어긋난 자동 점: 끌거나, 클릭 후 화살표로 옮긴다. 그러면 같은 이름의 손 점이 되고, 손 점이 자동 점보다 우선한다.
   - 손 점을 고쳤으면 Enter를 한 번 더 눌러도 된다.
5. **계산 결과**: 기준점 오차(목표 0.5cm 안), 렌즈 위치, 재투영 오차(가장자리 / 가운데)를 본다.
6. 나머지는 v1과 같다: ② 감시 칸, ③ 꼭짓점, ④ 보조선, S 저장.
7. **판정**:

```bash
python occupancy.py --run config/run_v2.json
```

## 4. 화면 색과 모양

| 모양 | 뜻 |
|---|---|
| 동그라미 + 십자 | 손 점 (v1과 같음). 초록 = 오차 0.5cm 안, 빨강 = 넘음 |
| 빨간 겹원 + "!" | 자동으로 찾은 선과 1cm 넘게 어긋난 손 점. 계산에서 뺐다. 옆 칸에 찍었거나 이름이 틀린 것 |
| 초록 마름모 | 자동 점, 두 선 모두 "찾음" |
| 노랑 마름모 | 자동 점, "애매함" 선에서 나옴 (확인할 것) |
| 회색 작은 마름모 | 찾았지만 다른 점들과 맞지 않아 안 씀, 또는 같은 이름의 손 점이 있어 안 씀 |
| 회색 X | 관리자가 뺀 자동 점 |
| 분홍 네모 | 클릭으로 고른 자동 점 |
| 기준선 초록 / 노랑 / 회색 | 찾음 / 애매함 / 못 찾음. 가는 선 = 지금 계산으로 예상한 자리, 굵은 선 = 찾은 선 |

"찾음" 기준(설정 값으로 바꿀 수 있음): 찾은 점의 절반 넘게가 직선 위, 예상 길이의 40% 넘게를 덮음, 직선에서 1.2픽셀 안. "애매함"은 덮은 길이 15%, 2.5픽셀까지.

| 키 / 마우스 | 하는 일 |

## 6. 기준선 목록 만드는 법

### 6.1 형식

```json
{
 "lines": [
  {"id": "14-L", "kind": "edge", "p1": [26.4, 9.5], "p2": [26.4, 2.8], "floor_dir": [1, 0], "width": 0.25},
  {"id": "T15-27-2", "kind": "tip_row", "p1": [15.3, 9.5], "p2": [44.9, 9.5], "tip_dir": [0, 1]},
  {"id": "S0", "kind": "center", "p1": [100, 100], "p2": [100, 600], "width": 12}
 ],
 "points": [
  {"id": "14-IE-", "a": "14-L", "b": "T15-27-2", "mat": [26.4, 9.5]}
 ],
 "scan": {"search": [60, 30, 15]}
}
```

(위 숫자는 형식 예시다. 실제 값은 data\기준선_매트.json 을 본다.)

| 항목 | 뜻 |
|---|---|
| id | 이름. 기준점 id는 칸 표 기준점 이름(예: 14-IE-)과 같게 하면 손 점과 같은 점으로 다룬다 |
| kind | `edge` 칠한 선의 한쪽 가장자리 / `center` 가는 선의 가운데 / `tip_row` 여러 선의 끝을 이은 가상선 |
| p1, p2 | 매트 좌표 선분 (칸 표와 같은 단위). edge·center는 실제로 칠한 구간만 적는다 |
| floor_dir | edge만. 바닥(선이 아닌) 쪽 매트 방향. 그쪽 가장자리를 찾는다 |
| tip_dir | tip_row만. 선 끝이 향하는 방향. 그 방향으로 가장 먼 끝점들을 잇는다 |
| width | 선 폭(선택). 엉뚱한 선(글자, 화살표)을 거르는 데만 쓴다 |
| bright | 선이 바닥보다 밝은지(선택, 기본 true). 밝은 바닥에 어두운 선이면 false |
| points | 기준점 = 기준선 a, b 의 교점. `mat`은 두 선의 교점과 같아야 한다(읽을 때 확인, 허용 0.02) |
| scan | 이 주차장에 맞춘 설정(선택). 7절 이름만 쓴다. 모르는 이름이면 읽을 때 알린다 |

목록을 읽을 때 형식, 교점, 설정 이름을 확인하고 틀리면 무엇이 틀렸는지 알려 준다.

### 6.2 이 매트

```bash
python make_ref_lines.py
```

칸 표(data\칸표_매트좌표_초안.json)에서 data\기준선_매트.json 을 만든다. 칸 표가 바뀌면 다시 돌린다(손으로 고치지 않는다). 파일이 없으면 calibrate_v2.py가 시작할 때 저절로 만든다.

- 칸 옆: U자 다리의 칸 쪽 가장자리(edge, 바닥 쪽 = 칸 안쪽). 같은 묶음에 맞닿은 이웃이 있는 쪽만.
- 입구: 한 묶음의 U자 둥근 끝을 이은 tip_row. 기둥에서 묶음을 끊는다.
- 안쪽: 칸마다 카스토퍼의 칸 쪽 면(edge, 짧은 선분).
- 기준점: 칸 옆 ∩ 입구 = IE-/IE+, 칸 옆 ∩ 안쪽 = IB-/IB+.
- 기둥 옆, 줄 끝(반쪽 U자) 칸 옆은 칠한 모양이 달라 적지 않았다. 이 칸의 점은 손으로 찍는다.
- 모양 숫자(make_ref_lines.py 의 MAT_SHAPE): U자 다리 폭 0.25cm, 카스토퍼가 칸 양옆에서 떨어진 거리 0.4cm, 카스토퍼 두께 0.3cm. **실제 사진으로 아직 확인하지 않았다**(9절).

### 6.3 일반 주차장 예

test_autoref.py 의 `make_lot()` 이 예다(단위 cm, 칸 폭 250, 깊이 500, 선 폭 12).

- 직사각형 칸 10개
  - 칸 사이 선 11개: `center`, S0~S10 (x = 100 + 250·i, y 100~600)
  - 안쪽 선: `center` BACK (y = 600)
  - 앞쪽은 선이 없고 칸 사이 선 끝만 있다: `tip_row` FRONT (y = 100, tip_dir (0, -1))
  - 기준점 R{i}-front = S{i} ∩ FRONT, R{i}-back = S{i} ∩ BACK
- 비스듬한 칸 4개 (60°)
  - 칸 사이 선 A0~A4: `center`, 기울어진 선분
  - 앞선 AFRONT, 뒷선 ABACK: `center`
  - 기준점 A{i}-front, A{i}-back
- `scan`: 단위가 cm라 매트 단위 값을 크게 한다: `"search": [60, 30, 15], "floor_clear": 30, "manual_warn": 30, "point_tol": 0.5`

코드는 그대로이고 데이터만 다르다. 칸 표가 "선 가운데 기준"이면 center, "선 안쪽 기준"이면 edge를 쓴다.

## 7. 설정 값

실행 설정 config\run_v2.json 의 `autoref` 와 기준선 목록의 `scan` 이 parkit_autoref.py 의 `DEFAULTS` 를 덮어쓴다(나중 것이 이김: DEFAULTS < autoref < scan). 매트 단위(이 매트는 cm) 값은 주차장 단위에 맞춘다.

| 이름 | 기본 | 뜻 |
|---|---|---|
| search | [2.0, 1.0, 0.5] | 찾는 폭(매트 단위, 예상선 양쪽). 회차마다 다음 값. 손 점이 많이 틀릴 수 있으면 첫 값을 키운다 |
| sample_step_px / tip_step_px | 5 / 2 | 단면 간격(화면 픽셀) |
| min_samples | 12 | 짧은 선도 단면을 이만큼은 뽑는다 |
| end_margin | 0.1 | 선분 양 끝에서 비우는 비율 |
| min_contrast | 20 | 선과 바닥의 밝기 차 최소값(0~255). 어두운 조명이면 낮춘다 |
| rel_strength | 0.8 | 가장 센 후보의 이 비율 이상인 후보 중 예상선에 가장 가까운 것을 고른다. 낮추면 처음 넓게 찾을 때 옆의 약한 나란한 선(중앙 분리선 등)을 잡을 수 있다 |
| floor_clear, floor_clear_factor | 0.6, 2.5 | edge·tip: 바닥 쪽이 이만큼 비어 있어야 한다 (선 폭 × factor 와 큰 쪽) |
| width_tol | [0.4, 2.5] | 잰 선 폭 / 적힌 선 폭 허용 범위 |
| max_search_px | 220 | 화면에서 찾는 폭의 최대값 |
| ransac_px, ransac_iter | 1.5, 150 | 직선 RANSAC |
| min_points, min_points_tip | 6, 3 | 직선 하나에 필요한 점 수 |
| found_ratio, found_coverage, found_rms_px | 0.5, 0.4, 1.2 | "찾음" 기준 |
| amb_coverage, amb_rms_px | 0.15, 2.5 | "애매함" 기준 (못 미치면 못 찾음) |
| min_angle_deg | 15 | 교점을 만드는 두 선의 최소 각도 |
| h_ransac_px, h_prune_px | 2.0, 1.5 | 자동 점 호모그래피 RANSAC 문턱, 맞춘 뒤 뺄 잔차 (화면 픽셀) |
| manual_warn | 1.0 | 손 점이 자동 결과와 이만큼(매트 단위) 넘게 어긋나면 경고하고 뺀다 |
| min_auto_points, min_total_points | 4, 8 | 자동 점이 4개, 손 점과 합쳐 8개가 안 되면 자동 결과를 쓰지 않는다 |
| use_ambiguous | true | 애매한 선의 교점도 쓸지 |
| border_frac | 0.15 | 재투영 비교에서 "가장자리"로 볼 화면 폭 |
| point_tol | 0.02 | 기준점 좌표 = 교점 허용 오차 |
| min_spread | 0.01 | 손 점이 한 줄로 서 있는지 보는 기준 |

## 8. 결과 파일 (config\v2\cam_<이름>.json)

v1과 같은 키(ref_points, homography, pose, monitored, edited_corners, expected_contact …)에 더한 것:

- `ref_points` 의 자동 점에 `"auto": true`
- `auto_ref`
  - `ref_lines`: 쓴 기준선 목록, `settings`: autoref 설정, `use_auto`
  - `manual_points`: 손 점 전부(경고로 계산에서 뺀 점도 남긴다. 다시 열 때 이것을 읽는다)
  - `manual_bad`: 경고 받은 손 점과 어긋난 거리
  - `excluded`: 관리자가 뺀 자동 점
  - `autos`: 찾은 자동 점 전부(쓴 것, 안 쓴 것)와 상태
  - `counts`, `last_run`(선 찾음/애매/못 찾음 수, 회차별 점 수), `edge_report`(가장자리/가운데 재투영 오차)

원본 occupancy.py 는 `auto_ref` 를 읽지 않는다.

## 9. 시험 결과와 확인한 것

참 기준점 4개에 ±8픽셀 잡음을 넣고 시작한다. 기준: 보이는 모든 기준점 오차 평균 0.15cm, 최대 0.3cm 안, 렌즈 위치 0.5cm 안.

## 10. 안 될 때

| 증상 | 볼 것 |
|---|---|
| "손 점이 4개 이상 있어야" | 손 점을 4개 이상 찍는다 |

| "자동 점이 손 점 N개 중 M개와 맞지 않습니다" | 손 점 여럿이 틀렸다. 옆 칸에 찍은 점, 화면 밖 점을 지우고 다시 찍는다 |

| 모든 자동 점이 칸 하나만큼 밀려 있다 | 손 점 4개가 모두 같은 칸 수만큼 밀려 찍혔다(무늬가 되풀이되어 프로그램은 알 수 없다). 칸 번호를 확인하고 다시 찍는다 |
| "기준선 목록 오류" | 알려 준 줄을 고친다. 이 매트는 손으로 고치지 말고 make_ref_lines.py 로 다시 만든다 |

## 11. 남은 문제

- 실제 사진 v1/v2 비교(9.5절)는 그림이 그려진 화면 저장을 메워서 했다. 그림 없는 원본 사진으로 한 번 더 하는 것이 좋다.
- U자 다리 폭(실제 약 0.33cm), 줄 깊이를 자로 재서 칸 표와 make_ref_lines.py 모양 값을 확인해야 한다.
- 실제 화면에서 줄마다 깊이가 0.2~0.5cm 어긋난다(9.4절). 칸 표, 모양 가정, 매트 평평함 중 무엇인지 가려야 한다.
- 칸 번호가 U자 끝 바깥에 있는 줄(1~14번)은 tip_row가 글자를 잡을 수 있다. 그 줄은 입구 기준선을 빼거나 손 점을 쓰는 것을 검토한다.
- 렌즈 왜곡 보정은 하지 않는다. 가장자리/가운데 재투영 오차만 보여 준다.
- 기둥 옆, 줄 끝 칸 옆은 기준선이 없다(실제 모양 확인 후 make_ref_lines.py 에 더할 수 있다).
- 손 점 4개가 모두 같은 칸 수만큼 밀리면 알아챌 수 없다(10절).
- make_handoff.py 는 config\v2\ 와 data\기준선_매트.json 을 담지 않는다(원본 도구라 고치지 않았다). 받는 쪽은 calibrate_v2.py 를 처음 열 때 기준선 목록이 저절로 만들어지고, v2 보정은 새로 한다.
- 자동 찾기는 4초쯤 걸리고 그동안 화면이 멈춘다.
