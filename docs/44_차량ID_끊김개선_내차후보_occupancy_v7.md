# 44. 마주 지나가는 차의 ID 끊김 줄이기와 "내 차 후보" → occupancy_v7 (2026-11-08)

웹 지도에서 두 차가 마주 지나가면 차량 ID가 새로 붙어, 이용자가 내 차를 처음부터 다시 찾아야 했다. 두 가지를 했다.
1. **추적 규칙 개선:** ID가 덜 끊기게 했다.
2. **내 차 후보:** 그래도 끊기거나 섞이면 웹 지도가 내 차를 이어 주거나, 내 차일 수 있는 차를 보여 준다.

`occupancy_v6`를 `occupancy_v7`로 복사해서 고쳤다(`logs`, `__pycache__`, `node_modules` 제외). v6는 그대로 두었다. 칸 판정은 v6와 같다. 커밋하지 않았다.

## 1. 지금 추적기가 같은 차로 보는 규칙 (v6까지)

차의 생김새는 보지 않고 **매트 위 위치(접점)만으로** 정한다.
1. 차마다 예상 위치 = 마지막 위치 + 속도 × 지난 시간 (최대 0.7초까지 내다봄)
2. 새 점이 예상 위치에서 허용 거리(최대 10cm, 다른 카메라 점은 2cm) 안이면 같은 차일 수 있음
3. 가장 가까운 짝끼리 잇는다
4. 점 하나가 두 차에 거의 같은 거리로 가까우면(0.65cm 차이 이하) **애매해서 잇지 않는다**(ID가 서로 바뀌는 것을 막으려고)
5. 안 이어진 점은 새 차 후보 → 몇 번 더 잡히면 새 ID
6. 1.2초 넘게 갱신이 없으면 "놓침". 이때부터는 **멈춘 자리 2cm 안**에서만 다시 잇는다. 4초 넘으면 끝

**마주 지나갈 때 끊기는 과정:** 엇갈리는 0.5~1초 동안 4번 때문에 잇지 않는다. 그 시간이 1.2초를 넘으면 6번에 따라 2cm 안에서만 다시 찾는데, 그 사이 차는 5~7cm 움직였으므로 새 ID가 된다.

## 2. 추적 규칙 개선

| 바꾼 것 | 내용 | 설정 (기본) |
|---|---|---|
| 놓친 차 다시 찾기 | 멈춘 자리 2cm 대신, **놓친 동안 지난 속도로 갔을 곳** 근처에서 다시 찾는다. 반경 = 4cm + 0.5 × 속력 × 놓친 시간 | `reacquire_radius_cm` 4.0, `reacquire_speed_frac` 0.5, `reacquire_horizon_s` 3.0 |
| 가린 차는 시선 구간 | 가린 차를 점 하나(앞차 뒤 끝)가 아니라 **시선 위 구간**(앞차 뒤 끝 ~ 잘린 접점)으로 보낸다. 이미 아는 차면 구간 위에서 그 차의 예상 위치와 가장 가까운 점을 쓴다. 대각선 카메라에서 앞차 뒤 끝과 실제 뒤차 사이가 5cm 넘게 벌어지던 것을 줄인다 | (없음) |
| 대략 위치 벌점 | 대략 위치(가림·화면 끝)의 비교 값에 벌점을 더해, 같은 차를 두고 다투면 정확한 점이 먼저 이어진다 | `approx_penalty_cm` 0.7 |
| 엉뚱한 칸 막기 | 가린 차를 칸 예상 접점에 놓는 것은 시선 점에서 6cm 안일 때만. 더 멀면 판정이 칸을 잘못 고른 것으로 보고 시선 점을 쓴다 | 판정 설정 `approx_slot_max_cm` 6.0 (`run.json`) |

추적 설정은 `run.json`의 `vehicle_tracking` 또는 `--tracking-config` 파일로 바꾼다(`tracking_config.example.json`).

## 3. 내 차 후보

### 서버가 보내는 것
- **섞였을 수 있는 차 (`vehicles[].related`):** 4번 규칙 때문에 애매해서 못 이은 차들이, 같은 점을 두고 다툰 차를 서로 가진다. 1.2초 동안 남는다.
- **뒤를 이을 수 있는 차 (`successors`):** 어떤 차를 놓친 뒤 그 차가 갔을 법한 곳(6cm + 0.5 × 속력 × 놓친 시간 안)에 새 ID가 생기면 "옛 ID → 새 ID"를 30초 동안 기억해 보낸다. 설정은 `link_radius_cm` 6.0, `link_speed_frac` 0.5, `link_keep_s` 30.

### 웹 화면 (`web/src/tracking.js`의 `myCarState`)

| 내 차 상황 | 지도 | MY VEHICLE 칸 |
|---|---|---|
| 그대로 | 보통 | 보통 |

- [아니에요]를 누르면 원래 차로 돌아가고, 그 후보는 빼고 다시 판단한다(다른 후보가 있으면 고르기, 없으면 마지막 위치).
- 이은 차가 또 끊기면 그 뒤를 이은 차까지 따라간다.
- "내 차만 보기"를 켜 두었어도 후보들은 보인다. 범례에 "내 차 후보"가 나온다.

## 4. 시험

### 4.1 합성 시험 `test_crossing.py`
- **장면 3가지:**
  - 마주 지나감: 옆 간격 1.75, 2.5cm
  - 같은 방향 줄지어 감: 앞뒤 8cm
  - 주차된 차 옆 지나감
- 각 장면을 카메라 4곳(남쪽·북쪽 정면, 대각선 2곳) × 통로 2곳 × 상자 모델 2가지 × 속도 2가지(초속 5, 8cm)로 돌렸다. 분석은 초당 2장이다.
- **상자 모델 cut:** 뒤차 아래가 앞차에 가려지는 것만 넣었다.
- **상자 모델 real:** cut에 더해, 옆이 가려지면 폭이 줄고 두 상자가 거의 겹치면(IoU 0.7 넘음) 하나가 사라지게 했다.
- **ID 끊김:** 한 차에 확정 ID가 새로 붙은 횟수. **ID 바뀜:** 한 ID가 두 차에 붙은 횟수. 둘 다 **2프레임 연속** 붙은 것만 센다. 한 프레임 튄 것은 이용자가 고른 ID를 바꾸지 않기 때문이다.
- 숫자는 횟수 또는 경우의 수다.

| 코드 | 마주 지나감 끊김 | 주차 차 옆 끊김 | 줄지어 감 끊김 | ID 바뀜 | 내 차를 끝까지 따라감 |

## 5. 남은 문제

- **실제 웹캠으로 확인하지 않았다.** 미니카 두 대를 통로에서 마주 지나가게 하고, ID가 유지되는지, 끊기면 "내 차(추정)"나 "내 차 후보"가 나오는지 본다.
- **합성 시험의 한계:** 상자는 차 모양에 꼭 맞고, 흔들림은 ±3px까지만 넣었다. 실제 YOLO가 두 차를 상자 하나로 합치거나 몇 프레임 놓치면 더 끊길 수 있다. 그때는 "내 차 후보"가 받친다.
- **화면 끝으로 나가는 차:** 앞차가 화면 끝으로 나갈 때 그 대략 위치(화면 끝 상자)가 실제보다 늦게 따라와, 같은 방향으로 뒤따르는 차와 가까워질 수 있다. 줄지어 감 32가지 중 4가지에서 "내 차가 다른 차 근처"로 보였다. v6에서도 같다.
- **위치만 보는 한계:** 생김새를 보지 않으므로 두 차가 딱 붙어 엇갈리면 여전히 애매하다. 이때는 이어 붙이지 않고 "내 차 후보"로 묻는다. 차 색깔을 같이 보는 방법은 다음 단계 후보다.
- **자동 이음은 추정이다.** 후보가 하나뿐이라도 틀릴 수 있어 "추정"과 [맞아요]/[아니에요]를 늘 보여 준다.
- 분석 간격을 줄이면(초당 2장 → 6장) 엇갈림이 더 짧아져 도움이 된다(43 문서 뒤 분석).
- 웹을 고치면 `web`에서 `npm ci`, `npm run build`를 다시 해야 한다. git에 올릴 때 `web/dist`는 `git add -f`가 필요하다.
