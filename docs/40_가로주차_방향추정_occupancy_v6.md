# 40. 가로 주차 방향 추정 → occupancy_v6 (2026-11-07)

칸에 선 차가 **세로**(칸과 같은 방향)인지 **가로**(칸과 수직)인지 고르고, 가로로 고른 차는 걸침(P3) 범위를 차 길이만큼 넓혔다. 가로로 2칸·3칸을 막은 차의 칸이 모두 "차 있음"이 된다. 39 문서 A5절의 "방향 추정"을 판정 프로그램에 넣은 것이다.

- `docs\도구\occupancy_v5`를 `occupancy_v6`로 복사해서 고쳤다(`logs`, `__pycache__` 제외). v5와 v5 설정 파일은 고치지 않았다.
- 비스듬히(기울여) 선 차는 다루지 않았다(39 문서 A5-2).
- 커밋하지 않았다.

### 방향 고르기 (`_assign`)

1. 상자 바닥 접점을 칸마다 그 칸 좌표로 바꾸고, 판정 구역(깊이) 안인 칸만 본다(v5와 같음).
2. 칸마다 두 후보를 본다.
   - 세로: 예상 접점과 x 거리 ≤ `expect_max_dist_cm`(2.0, v5와 같음)
   - 가로: x 거리 ≤ `expect_max_dist_side_cm`(2.5), 깊이 거리 ≤ `expect_max_depth_side_cm`(1.5)
3. 후보마다 비교 값을 낸다.
   비교 값 = 0.5 × |x 차이| + 1.0 × |깊이 차이| + 3.0 × (|log(상자 폭 / 예상 폭)| + |log(상자 높이 / 예상 높이)|)
4. 가로 최선이 세로 최선보다 `orient_margin`(0.4) 넘게 작으면 **가로**로 고른다.
5. 차이가 그보다 작으면 **세로**로 고른다. 이때 가로였다면 더 막았을 칸은 그 프레임만 **"모름"**으로 둔다. "모름"은 상태를 바꾸지 않는다. 그 칸에 차가 직접 잡히면 "차 있음"이 이긴다.
6. 그 밖에는 세로.

- 크기를 믿을 수 없는 상자(아래가 잘림, 옆이 가려짐, 화면 끝에 닿음)와 카메라 자세가 없는 설정은 v5와 같이 세로로만 본다. P2a 구간 위의 점도 크기가 없어서 세로로만 본다.
- `orientation_enable: false`면 모든 상자가 v5 코드 길로 간다. 시험에서 v5와 결과가 같았다(4절).

## 3. 새 설정값

`parkit_config.py` 기본값이다. `run.json`의 `params`, `overrides`로 바꾼다. 줄·칸별로도 줄 수 있다.

| 이름 | 기본 | 뜻 |
|---|---|---|
| `orientation_enable` | true | 방향 추정. false면 v5와 같다 |
| `orient_x_weight` | 0.5 | 비교 값의 x 차이 가중치 |
| `orient_depth_weight` | 1.0 | 비교 값의 깊이 차이 가중치 |
| `orient_size_weight` | 3.0 | 비교 값의 상자 크기 비 가중치 |
| `orient_margin` | 0.4 | 가로를 고르려면 세로보다 이만큼 넘게 잘 맞아야 한다. 애매하면 "모름" (5절) |
| `expect_max_dist_side_cm` | 2.5 | 가로 차의 예상 접점과 x 거리 한계. 두 칸 사이에도 서므로 칸 폭 절반(약 2cm)보다 크게 |
| `expect_max_depth_side_cm` | 1.5 | 가로 차의 예상 접점과 깊이 거리 한계 |

`straddle_min_cm`(run.json 0.1)은 바꾸지 않았다.

## 5. 정해야 할 것: `orient_margin` 0.4와 0

요청의 두 완료 조건 "②③은 전부 맞음"과 "v5 시험 통과"는 **한 값으로 함께 채워지지 않았다.**

| | 여유 0.4 (지금 기본) | 여유 0 |
|---|---|---|
| test_geometry | 45 / 45 | **42 / 45**. 대각선 칸 고르기 644 / 756, 642 / 756, 반대 대각선 63 / 81이 실패 |
| CAM-2 ②③ 가로 주차 | 193 / 207, 101 / 115 (모름 13·13, 놓침 1·1) | **207 / 207, 115 / 115** |
| CAM-2 ① 세로 차 | 틀림 23·37 (v5와 같음), 모름 90 | 빈 칸을 차 있음으로 38 (v5 23) |

- **왜 갈리나:** 대각선 카메라에서 시선이 45° 가까우면, 세로 차(3.2 × 6.5)와 가로 차(6.5 × 3.2)를 감싸는 상자가 거의 같다. YOLO 상자는 숫자 4개뿐이라 구별할 정보가 없다. test_geometry의 대각선 시험은 크기가 다른 세로 차(폭 2.8~3.6, 길이 6.0~7.0, 좌우 ±1cm, 깊이 0.5cm)가 "옆 칸을 막지 않음"이기를 요구한다. 여유 0에서는 그중 일부를 가로로 골라 빈 옆 칸이 "차 있음"이 된다.
- **0.4로 둔 까닭:** v5에서 보장하던 것(바르게 선 차는 옆 칸을 막지 않음)을 깨지 않고, 방향 추정 때문에 새로 생기는 틀린 답이 없다. 39 문서 A5-2의 "구별이 안 되면 모름"과 같은 생각이다.
- **0을 고를 까닭:** 손님에게 "빈 칸인데 막혔다"고 하는 것(빈 칸을 차 있음으로)보다 "막힌 칸을 비었다"고 하는 것(놓침)이 더 나쁘다고 보면 0이 낫다. 가로 주차는 모두 잡고, 대신 대각선에서 바르게 선 차의 옆 칸을 가끔 막힌 칸으로 낸다.
- "모름" 칸은 상태를 바꾸지 않는다. 그래서 가로 차가 막은 칸이 "모름"이면, 그 칸은 직전 상태(대개 EMPTY)로 남는다. 놓침과 비슷하게 보일 수 있다. 2대 시연에서는 다른 카메라가 그 칸을 확실히 보면 카메라 합치기(P9)로 풀린다.
- 바꾸려면 `config\run.json`의 `orient_margin`만 고친다. 기본값을 바꾸면 test_geometry 기대값도 바뀐다.

## 6. 39 문서 숫자와 다른 점

- **CAM-1 보정이 바뀌었다.** 39 문서는 렌즈 (-27.6, 22.8, 높이 8.9cm)의 낮은 측면 카메라로 계산했다(CAM-1 ① 360가지). 지금 v5·v6의 `cam_CAM-1.json`은 11-07 19:28에 다시 보정한 것이다. 렌즈 (34.9, 68.9, 높이 36.9cm), 감시 칸 33개라 ① 255가지다. 그래서 CAM-1 숫자는 39 문서와 비교할 수 없다.

## 8. 남은 문제

- **실제 YOLO 상자로 확인하지 않았다.** 위 결과는 합성 상자(차 모양에 꼭 맞는 상자)와 ±3px 흔들림이다. YOLO 상자는 크기가 더 흔들리고, 가로로 선 미니카를 학습 사진에서 얼마나 봤는지도 모른다. 방향을 잘못 고를 수 있다. 가로 2칸·3칸 주차를 실제로 세워 보고 `horiz` 표시와 칸 결과를 본다.
- **대각선 카메라는 구별이 어렵다**(5절). 2대 시연이면 정면에 가까운 카메라가 방향을 잘 고르므로, P9 합치기에서 그 카메라를 믿게 하는 규칙을 생각할 수 있다.
- **크기를 믿을 수 없는 상자는 세로로만 본다.** 화면 끝에 닿은 가로 차(CAM-1 2번 근처), 앞차에 아래가 잘린 가로 차, 옆이 가려진 가로 차는 옆 칸을 놓칠 수 있다.
- **감시하지 않는 칸에 고른 가로 차**는 v5처럼 걸침을 보지 않는다. 그 차가 감시 칸까지 막아도 "차 있음"이 되지 않는다.
- **차 크기가 3.2 × 6.5와 다르면** 방향을 잘못 고르기 쉽다. 시연 차를 재서 `car_width_cm`, `car_length_cm`에 넣는다.
- 비스듬히 선 차(39 문서 A5-2)는 이번에 다루지 않았다.
- `run_2대.json`은 기본값(여유 0.4)을 쓴다. 2대 시연 전에 같이 정한다.
