## 1. 데이터가 많을수록 무조건 좋은가

**아니다. 하지만 "라벨이 맞고, 실제로 쓸 환경과 닮은 데이터"는 거의 항상 도움이 된다.** 데이터를 더했는데 나빠지는 경우는 대부분 아래 넷 중 하나다.

1. **라벨이 틀린 데이터.** 2차·4차는 best.pt가 만든 라벨이라, 검수하지 않으면 best.pt의 실수(놓친 차, 두 대를 한 상자로 묶음)를 그대로 다시 배운다.
2. **차 없는 사진이 너무 많음.** 3차 30장과 COCO 60장을 다 넣으면 90장으로, 차 있는 사진 119장의 76%다. 모델이 "웬만하면 차가 아니다" 쪽으로 기울어 차를 놓치기 쉽다. 차 없는 사진은 전체의 10~20%가 적당하다(14 문서). 지금 기준으로 15~25장, 예를 들어 3차 15장 + COCO 10장.
3. **거의 같은 사진이 많음.** 같은 배치를 조금씩 각도만 바꾼 사진은 새 정보가 적다. 2차의 `중복` 폴더를 뺀 이유와 같다.
4. **시연 환경과 다른 데이터만 늘어남.** 시연을 학교에서 한다면 학교 사진(2차)이 집 사진보다 훨씬 중요하다.

그래서 "1차만 학습한 모델이 더 좋을 수도 있다"는 걱정은 맞는 걱정이다. 다만 그런 결과는 보통 **시험 사진이 1차와 같은 환경(집)뿐일 때** 나온다. 1차만 배운 모델은 집 사진에서는 좋고, 학교 사진이나 차 없는 사진에서는 나빠질 가능성이 높다(추정). 그래서 시험 세트를 어떻게 만드느냐가 핵심이다.

## 2. 시험 세트 만들기: 출처별로 나눠서 고정

말씀대로 시험 사진의 출처에 따라 점수가 크게 달라진다. 그래서 **시험 세트를 출처별로 나눠 두고, 점수도 출처별로 따로** 본다. 하나의 합계 점수만 보면 어느 환경에서 좋아졌고 나빠졌는지 안 보인다.

### 지킬 규칙

- **학습 전에 시험 세트를 먼저 떼어 두고, 어떤 모델에도 학습시키지 않는다.** 모든 모델을 같은 시험 세트로 잰다.
- **배치 단위로 뗀다.** 같은 배치의 다른 방향 사진이 학습에 들어가면 시험이 쉬워진다. 1차 `handoff_1차`도 이미 배치 단위(test = A_7, B_6)로 나눠져 있다.
- **시험 세트 라벨은 사람이 꼼꼼히 검수한다.** best.pt가 만든 라벨을 덜 고친 채 정답으로 쓰면, best.pt의 실수가 정답이 되어 best.pt가 실제보다 좋게 나온다.
- 학습 중 어떤 모델·설정이 좋은지 고를 때는 val을 쓰고, test는 마지막 비교에만 쓴다.

### 제안하는 나누기

| 시험 세트 | 사진 | 보는 숫자 |
|---|---|---|
| T1 집 | 1차 test (A_7, B_6) 6장, 그대로 유지 | Precision, Recall, mAP50 |
| T2 학교 | 2차 중 2배치 (예: s8, s9) 12장 | 위와 같음 |
| T3 차 적음 | 4차 중 1배치 (예: little_car_4) 7장 | 위와 같음 |
| T4 빈 매트 | 3차 중 6장 (예: x_0025~0030, 연달아 찍은 묶음째) | 잘못 잡은 상자 수, 오탐 있는 사진 비율 |
| T5 외부 물체 | COCO `--seed 2`로 새로 30장 (학습용 seed 1과 다른 사진) | 위와 같음 |
| T6 최종 시험 (권장) | **다른 날 학교에서 새로 찍은 사진.** 새 배치 몇 개 + 매트 위에 지우개·병·손 같은 물체를 같이 둔 사진 | 위 두 종류 모두 |

val도 같은 방식으로 출처마다 1배치 정도씩 뗀다(1차는 지금처럼 A_6, B_5). 나머지가 학습용이다.

T6이 가장 정직한 시험이다. 모든 학습이 끝날 때까지 아무도 보지 않은 사진이고, 실제 시연 환경과 같다. 교수님께 보여 드릴 최종 숫자는 T6(과 T2)가 좋다.

## 3. 어떤 숫자로 비교하나

"성공률" 하나로는 부족하다. 차가 있는 사진과 없는 사진은 다른 숫자로 본다.

- **차가 있는 사진 (T1~T3, T6):**
  - Recall: 실제 차 중 몇 %를 찾았나
  - Precision: 잡은 상자 중 몇 %가 진짜 차인가
  - mAP50: 신뢰도 기준과 상관없는 종합 점수
  - Ultralytics의 `model.val(data=...)`이 세 숫자를 다 준다. 시험 세트마다 data.yaml을 따로 만들어 돌리면 된다.
- **차가 없는 사진 (T4, T5, T6 일부):** 사진 한 장당 잘못 잡은 상자 수, 오탐이 하나라도 있는 사진 비율. 14 문서에서 best.pt는 COCO 60장 중 51장에서 오탐이 있었다.
- **주차장 용도로 본 숫자 (선택):** 사진마다 "잡은 차 수 = 실제 차 수"인 비율. 주차 칸 점유 판단에 바로 이어지는 숫자다.

신뢰도 기준은 모든 모델에 같은 값(예: 0.25, 또는 실제 프로그램에서 쓸 값)을 쓴다.

## 4. 비교 실험 계획

같은 학습 설정(에폭, imgsz, 시드)으로 데이터 조합만 바꿔 학습하고, 2절의 같은 시험 세트로 잰다.

| 모델 | 학습 데이터 | 확인하려는 것 |
|---|---|---|
| M1 | 1차 | 지금 best.pt와 같은 조건. 기준선 |
| M2 | 1차 + 2차 | 학교 사진을 넣으면 T2가 오르나 |
| M3 | 1차 + 2차 + 4차 | 차가 적은 장면이 도움이 되나 |
| M4 | M3 + 차 없는 사진 약 15장 (3차 8장 + COCO 7장, train 차 사진 약 77장의 20%) | 오탐이 줄어드나, 차를 덜 찾게 되지는 않나 |
| M5 | M3 + train용 차 없는 사진 전부 (3차 21장 + COCO 60장) | 차 없는 사진이 너무 많으면 어떻게 되나 |

결과는 아래처럼 한 표로 정리하면 어느 데이터가 무엇을 바꿨는지 바로 보인다.

| 모델 | T1 mAP50 | T2 mAP50 | T3 mAP50 | T4 오탐 사진 비율 | T5 오탐 사진 비율 | T6 |
|---|---|---|---|---|---|---|
| M1 | | | | | | |
| ... | | | | | | |

주의할 점:
- 사진이 적어서 같은 데이터로 다시 학습해도 점수가 몇 % 흔들린다. 시간이 되면 M1과 최종 후보만이라도 시드를 바꿔 두 번 학습해 본다. 차이가 그 흔들림보다 작으면 "같다"고 본다.
- 예상(추정): M1은 T1에서 가장 좋거나 비슷하고, T2·T4·T5에서 가장 나쁠 것이다. M4가 전체적으로 가장 균형이 좋을 가능성이 높다.

## 5. 순서

1. 2차·4차 라벨 검수를 마친다. 시험 세트에 들어갈 배치(T2, T3)부터 꼼꼼히 한다.
2. 2절대로 test·val·train을 나눈 폴더를 만든다.
3. COCO 시험용 30장을 `--seed 2 --out ...\data_neg_coco_test`로 만든다.
4. M1~M5를 학습하고 표를 채운다.
5. 다른 날 학교에서 T6을 찍어 최종 후보 1~2개만 잰다.

2번(나누기)과 채점 스크립트는 Claude Code로 PC에서 준비하고, 4번 학습은 코랩에서 돌린다. Claude Code에 넘길 프롬프트는 16 문서.
