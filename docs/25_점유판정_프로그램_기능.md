# 25. 점유 판정 프로그램 기능 정리 (2026-11-01)

22 문서(판정 방법)를 코드로 옮길 때 프로그램이 갖춰야 할 기능을 정리한다. Claude Code에 넘길 프롬프트는 이 문서를 기준으로 만든다.
근거: 22 문서(판정 규칙), 11 문서(웹캠 배치), 02 문서(상태 4단계, 기준값 T1~T5), 05 문서(시나리오 S1~S9), 21 문서(M8 모델), `docs\칸표_매트좌표_초안.json`.

## 0. 큰 그림

프로그램 두 개와 설정 파일 두 종류로 나눈다.

| 구분 | 하는 일 | 언제 쓰나 |
|---|---|---|
| **보정 도구** | 카메라마다 호모그래피 구하기, 감시 칸 고르기, 칸 꼭짓점 고치기 | 카메라를 고정한 뒤 한 번, 밀렸을 때 다시 |
| **판정 프로그램** | M8로 차 찾기 → 칸마다 상태 판정 → 화면 표시·기록 | 시험과 시연 |
| 칸 표 (`칸표_매트좌표_초안.json`) | 칸 56개의 매트 좌표(cm). 카메라와 상관없음 | 이미 있음 |
| 카메라 설정 (카메라마다 파일 1개) | 입력, 호모그래피, 감시 칸, 고친 칸 꼭짓점 | 보정 도구가 만든다 |
| 실행 설정 (1개) | 쓸 카메라 목록, 모델, 신뢰도, 시간 값 | 사람이 고친다 |

**지켜야 할 원칙**
- 카메라 수(1대, 2대, 그 이상)와 감시 칸은 **설정 파일로만** 정한다. 코드 안에 칸 번호나 카메라 수를 적지 않는다.
- 어느 줄이든 같은 규칙으로 판정한다. 1~14번 줄만을 위한 코드를 따로 두지 않는다.
- 기존 `live_detect_winmac.py`, `capture_winmac.py`는 고치지 않는다. 웹캠 열기(DSHOW/MSMF 순서로 시도, MJPG), 영상 파일 재생 같은 부분은 참고해서 새 파일에 쓴다.
- Windows와 맥에서 모두 돈다(13 문서 3절).

아래 기능 번호 옆의 단계는 언제 필요한지다.
- **[1]** 웹캠 1대 시험에 필요 (먼저 만든다)
- **[2]** 웹캠 2대 최종 시연에 필요
- **[3]** 나중에 (시연 뒤 또는 여유 있을 때)

## 1. 공통 기능

| 번호 | 기능 | 단계 |
|---|---|---|
| C1 | **입력 열기**: 웹캠 번호, 영상 파일(mp4), rtsp 주소 중 하나를 카메라 설정의 `source`로 받는다. 해상도는 실행 설정에서 카메라마다 정한다(예: 1920×1080, 1280×720). 웹캠이 그 해상도를 지원하지 않으면 실제로 열린 해상도를 화면과 기록에 표시한다 | [1] |
| C2 | **영상 파일로도 똑같이 돌기**: 웹캠 대신 녹화한 mp4를 넣으면 같은 판정이 나온다. 같은 장면을 반복 시험하는 데 쓴다 | [1] |
| C3 | **칸 표 읽기**: json에서 칸마다 `inner`, `cell`, `entrance_y`를 읽는다. 57~59번처럼 없는 칸은 건너뛴다 | [1] |
| C4 | **좌표 변환**: 화면 픽셀 ↔ 매트 cm (호모그래피와 그 역). 칸을 손으로 고쳤으면 그 칸은 "칸 꼭짓점 ↔ 단위 사각형" 변환을 쓴다(22 문서 3.3절) | [1] |
| C5 | **칸 선 겹쳐 그리기**: 카메라 화면 위에 감시 칸의 `inner`와 판정 구역을 그린다. 보정 도구와 판정 프로그램이 같이 쓴다 | [1] |
| C6 | **해상도가 바뀌어도 보정 그대로 쓰기**: 호모그래피와 고친 칸 꼭짓점은 보정할 때의 해상도와 함께 저장한다. 실행 해상도가 다르지만 화면 비율이 같으면(16:9끼리) 픽셀 좌표를 비율만큼 바꿔 그대로 쓴다. 비율이 다르면(예: 640×480은 4:3이라 양옆이 잘림, 11 문서 5절) 다시 보정하라고 알리고 그 카메라는 멈춘다 | [1] |

## 2. 보정 도구

| 번호 | 기능 | 단계 |
|---|---|---|
| K1 | **카메라 고르기**: 실행할 때 카메라 이름(CAM-1 등)과 입력을 받는다. 그 카메라의 설정 파일이 있으면 불러온다 | [1] |
| K2 | **기준점 찍기**: 화면에서 점을 클릭하고 그 점의 매트 좌표를 정한다. 좌표를 손으로 쓰지 않도록 "3번 칸 U자 입구 왼쪽 끝"처럼 칸 표에서 고를 수 있는 목록을 준다. 6~8개, 깊이가 다른 줄을 섞도록 안내한다 | [1] |
| K3 | **호모그래피 계산**: 점이 4개 이상이면 `findHomography`로 계산한다. 점마다 오차(cm)를 표시하고, 오차가 큰 점을 지우거나 다시 찍는다 | [1] |
| K4 | **점 끌어 옮기기**: 찍은 점을 끌면 바로 다시 계산하고 칸 선을 다시 그린다 | [1] |
| K5 | **감시 칸 고르기**: 화면 안에 꼭짓점이 모두 들어오는 칸을 자동으로 골라 보여 주고, 사람이 칸을 클릭해 켜고 끈다 | [1] |
| K6 | **칸 꼭짓점 고치기**: 칸 하나를 골라 네 꼭짓점을 끌어 인쇄된 선에 맞춘다. 칸별 "초기화"로 호모그래피 결과로 되돌린다 | [1] |
| K7 | **저장**: 카메라 이름, 입력, 해상도, 기준점, 호모그래피, 감시 칸, 고친 칸 꼭짓점을 카메라 설정 파일 하나에 저장한다. 저장한 날짜도 남긴다 | [1] |
| K8 | **확인 사진 저장**: 칸 선을 겹친 화면을 이미지로 저장한다(보고서, 다음 보정과 비교용) | [1] |
| K9 | **ArUco 마커 자동 보정**: 매트 모서리에 마커를 붙여 기준점을 자동으로 찾는다(05 문서) | [3] |

## 3. 판정 프로그램

### 3.1 판정 (22 문서 4절)

| 번호 | 기능 | 단계 |
|---|---|---|
| P1 | **차 찾기**: 카메라마다 초당 1~2장을 M8로 돌린다. 모델 경로와 신뢰도(기본 0.25, 0.4까지 바꿀 수 있게)는 실행 설정에서 정한다 | [1] |
| P2 | **바닥 접점 → 칸**: 상자 아래 변 가운데 점을 매트 좌표로 바꾸고, 그 카메라의 감시 칸 중 판정 구역(`cell` 깊이 방향 ±1cm)에 들어간 칸을 고른다. 경계 근처면 칸 가운데가 가까운 쪽 | [1] |
| P3 | **두 칸 걸침(S8)**: 바닥 접점 ± 차 폭의 절반(차 폭은 설정값, 첫 값 3.2cm)으로 차 범위를 만들고, 옆 칸 `inner`에 1cm 이상 들어가면 그 칸도 찼다고 본다(26 문서 2절) | [1] |
| P2a | **아래가 잘린 상자**: 상자 아래 변이 더 앞의 다른 상자 안에 있으면 "접점 불확실"로 표시한다. 가리는 차 뒤 끝 ~ 바꾼 점 구간이 판정 구역 하나만 지나면 그 칸, 여러 칸이면 그 칸들을 "가려짐". 불확실하거나 옆이 가려진 상자는 P3에 쓰지 않는다(26 문서 1.6절) | [1] |
| P2b | **칸별 예상 접점 보정**: 보정 때 카메라 자세(`solvePnP`)로 칸마다 보통 크기 차의 예상 접점을 계산해 카메라 설정에 저장하고, 같은 줄에서 예상 접점이 가장 가까운 칸을 고른다. 카메라가 정면이든 대각선이든 같은 코드로 돈다(26 문서 5절) | [1] |
| P4 | **통로 차 거르기**: 어느 칸에도 안 들어간 점은 통로 차로 보고 칸 판정에 넣지 않는다 | [1] |
| P5 | **가림(DYNAMIC_BLIND)**: 통로 차의 상자가 칸의 화면 영역(칸 바닥과, 그것을 차 높이 약 2cm만큼 올린 모양을 합친 영역)을 기준(첫 값 30%) 이상 덮고, 이번 프레임에 그 칸에서 차가 직접 잡히지 않으면 "가려짐". 1초 넘게 이어지면 DYNAMIC_BLIND. 풀리면 3초/5초 판정을 다시 거쳐 확정(26 문서 3절) | [1] |
| P6 | **시간 거르기**: 차 있음 3초 → OCCUPIED, 차 없음 5초 → EMPTY. 켠 직후에는 첫 판정까지 DYNAMIC_BLIND. 시연용 짧은 값(1초, 2초)을 설정으로 바꿀 수 있게 한다 | [1] |
| P7 | **감시하지 않는 칸**: 어느 카메라의 감시 칸에도 없는 칸은 STATIC_BLIND | [1] |
| P8 | **판정 값 칸별로 바꾸기**: 여유 1cm, 차 폭 3.2cm, 걸침 1cm, 가림 30% 같은 값을 실행 설정에 두고, 특정 칸(예: 28~41번 줄)만 다르게 줄 수 있게 한다(22 문서 4.2절) | [1] |
| P9 | **카메라 2대 합치기**: 한 카메라만 보는 칸은 그 결과, 함께 보는 칸(34·35번)은 가려지지 않은 쪽, 둘 다 정상이고 답이 다르면 "차 있음" | [2] |
| P10 | **카메라 끊김**: 프레임이 30초 넘게 안 오면 그 카메라만 보는 칸은 DYNAMIC_BLIND. 다시 연결되면 원래대로 | [2] |
| P11 | **여러 카메라 동시에 돌리기**: 카메라마다 프레임을 따로 받고(스레드), 모델은 하나를 같이 쓴다. USB 대역폭 때문에 MJPG로 받는다 | [2] |

### 3.2 화면 표시

| 번호 | 기능 | 단계 |
|---|---|---|
| D1 | **카메라 화면**: 차 상자, 바닥 접점(점), 감시 칸 선을 상태 색으로 그린다(EMPTY 초록, OCCUPIED 빨강, DYNAMIC_BLIND 노랑, STATIC_BLIND 회색) | [1] |
| D2 | **매트 평면도**: 칸 표로 위에서 본 매트를 그리고 56칸을 상태 색으로 칠한다. 바닥 접점을 평면도에도 찍는다. 이 화면이 시연의 주 화면이 된다 | [1] |
| D3 | **칸 정보**: 칸을 클릭하면 상태, 이번 프레임 판정, 상태가 바뀌기까지 남은 시간, 어느 카메라가 봤는지 보여 준다 | [1] |
| D4 | **켤 때 칸 선 확인**: 처음 몇 초간 칸 선을 크게 겹쳐 보여 준다. 카메라가 밀렸는지 눈으로 확인하는 용도(22 문서 3.4절) | [1] |
| D5 | **카메라 2대 화면**: 두 카메라 화면을 나란히, 또는 하나씩 바꿔 가며 본다 | [2] |
| D6 | **시연 모드**: 평면도를 크게, 칸 상태 수(빈 칸 몇 개, 찬 칸 몇 개)를 같이 보여 준다 | [2] |

## 5. 파일 구성 (제안)

`docs\도구\` 아래에 새 폴더를 만든다. 이름은 만들 때 정해도 된다.

```
docs\도구\occupancy\
  calibrate.py          보정 도구 (K1~K8)
  occupancy.py          판정 프로그램 (P, D, L)
  parkit_geom.py        좌표 변환, 칸 표 읽기, 칸 선 그리기, 해상도 맞추기 (C3~C6)
  parkit_video.py       입력 열기 (C1, C2)
  config\
    run.json            실행 설정 (카메라 목록과 해상도, 모델, 신뢰도, 시간 값, 칸별 판정 값)
    cam_CAM-1.json      카메라 설정 (보정 도구가 만든다)
    cam_CAM-2.json
  logs\                 상태 변화, 프레임 기록, 저장 화면
```

실행 설정에 카메라를 1대만 적으면 1대로, 2대를 적으면 2대로 돈다.

## 6. 1대 시험 단계에서 "다 됐다"의 기준

1. CAM-1 자리 웹캠으로 보정 도구를 돌려 기준점 오차가 모두 0.5cm 안이고, 칸 선이 인쇄된 선과 눈으로 맞는다.
2. 감시 칸(계산으로는 1~7번, 34~41번)에 차를 하나씩 넣고 빼면 평면도에서 그 칸만 3초 뒤 빨강, 5초 뒤 초록이 된다.
3. 통로 A에 세운 차는 어느 칸도 바꾸지 않고, 칸을 가리면 그 칸이 노랑이 된다.
4. 두 칸에 걸친 차는 두 칸을 모두 빨강으로 만든다.
5. 녹화한 mp4로 돌려도 웹캠과 같은 결과가 나온다.
6. 실행 설정에 카메라를 하나 더 적는 것 말고는 코드를 고치지 않고 2대로 넘어갈 수 있다.

## 7. 정해야 할 것

- **판정 규칙 설명**: P2, P3, P5는 26 문서에 그림과 숫자 예로 풀어 썼다.
- **화면 도구**: 보정 도구는 마우스로 점과 꼭짓점을 끌어야 한다. OpenCV 창(`cv2.setMouseCallback`)만으로 만들면 의존성이 적다. 버튼과 목록이 많아지면 tkinter를 쓴다(`live_detect_winmac.py`가 이미 tkinter를 쓴다). 첫 버전은 OpenCV 창을 추천한다.
- **모델 형식**: M8.pt를 그대로 쓸지, 속도가 모자라면 ONNX로 바꿀지는 1대 시험에서 속도를 재고 정한다. ONNX로 바꿔도 모델 계산량은 같다. 다만 기본 내보내기(`imgsz=640`)는 입력이 640×640 정사각형으로 고정되어 16:9 화면에서 계산이 약 1.7배가 되므로, `imgsz=(384, 640)` 또는 `dynamic=True`로 내보낸다.
